# `@ahoo-wang/fetcher-decorator`

The decorator package turns class and method metadata into Fetcher requests. It
fits teams that want a stable service interface instead of assembling requests
at every call site.

## Install

```bash
pnpm add @ahoo-wang/fetcher @ahoo-wang/fetcher-decorator reflect-metadata
```

Enable `experimentalDecorators` and `emitDecoratorMetadata` in TypeScript, then
import `reflect-metadata` once at application startup.

## Define a service

```ts
import 'reflect-metadata';
import { ResultExtractors } from '@ahoo-wang/fetcher';
import {
  api,
  autoGeneratedError,
  body,
  get,
  path,
  post,
  query,
} from '@ahoo-wang/fetcher-decorator';

interface User {
  id: string;
  name: string;
}

@api('/users')
class UserService {
  @get('/{id}', { resultExtractor: ResultExtractors.Json })
  get(@path('id') id: string, @query('expand') expand?: string): Promise<User> {
    throw autoGeneratedError();
  }

  @post('', { resultExtractor: ResultExtractors.Json })
  create(@body() input: { name: string }): Promise<User> {
    throw autoGeneratedError();
  }
}
```

Decorated methods are replaced by request execution. Their bodies should only
throw `autoGeneratedError()` so accidental undecorated execution fails clearly.

## Class and method decorators

| API                                   | Purpose                                               |
| ------------------------------------- | ----------------------------------------------------- |
| `api(path, metadata?)`                | Set the service base path and shared request metadata |
| `endpoint(method?, path?, metadata?)` | Define a method with an explicit HTTP method          |
| `get`, `post`, `put`, `patch`, `del`  | HTTP method shortcuts                                 |
| `head`, `options`                     | Metadata and capability requests                      |

The DELETE shortcut is named `del` because `delete` is a JavaScript keyword.
Method metadata overrides matching class metadata.

## Parameter decorators

| API                | Maps an argument to                          |
| ------------------ | -------------------------------------------- |
| `path(name?)`      | URL path parameters                          |
| `query(name?)`     | URL query parameters                         |
| `header(name?)`    | Request headers                              |
| `body()`           | Request body                                 |
| `request()`        | Complete request initialization              |
| `attribute(name?)` | Exchange attributes consumed by interceptors |

Omitting a name uses reflected parameter metadata. For `path`, `query`,
`header`, and `attribute`, passing a plain object expands its entries.

## Execution

`ExecuteLifeCycle` describes the decorator request lifecycle. `EndpointReturnType`
can annotate generated method return types, and `ApiMetadata` /
`EndpointMetadata` are available when tooling needs to inspect configuration.

See [Declarative services](../recipes/declarative-services.md) for Fetcher
registration, inheritance, and an application-shaped example.
