# `@ahoo-wang/fetcher-decorator`

This package converts class, method, and parameter metadata into Fetcher
requests. Use it when a stable service interface is clearer than assembling a
request at every call site; use `Fetcher` directly for dynamic request shapes.

## Install

```bash
pnpm add @ahoo-wang/fetcher @ahoo-wang/fetcher-decorator
```

Enable `experimentalDecorators`. The package imports `reflect-metadata` itself;
applications do not need a separate startup import for these decorators.

## Decorator selection

| Need | API | Contract |
| --- | --- | --- |
| Shared service defaults | `@api(basePath?, metadata?)` | Class base path, headers, timeout, Fetcher, extractor, attributes, and return type. |
| Explicit verb | `@endpoint(method?, path?, metadata?)` | Method-level endpoint metadata. |
| Common verb | `@get`, `@post`, `@put`, `@patch`, `@del`, `@head`, `@options` | Shortcut for `@endpoint`; `@del` is DELETE. |
| URL parameters | `@path(name?)`, `@query(name?)` | Primitive uses its name; object expands its entries. |
| Header or body | `@header(name?)`, `@body()` | Header behaves like path/query; body is the single body value. |
| Per-call override | `@request()` | Accepts `ParameterRequest`, a `FetchRequestInit` plus optional `path`. |
| Interceptor data | `@attribute(name?)` | Primitive, object, or `Map` values populate exchange attributes. |

Use explicit names for path placeholders. Unnamed parameters are derived from
the function's runtime text, which minifiers can rename; the runtime warns when
a `{placeholder}` or `:placeholder` is not bound.

## Complete service example

```ts
import {
  Fetcher,
  ResultExtractors,
} from '@ahoo-wang/fetcher';
import {
  api,
  attribute,
  autoGeneratedError,
  body,
  get,
  path,
  post,
  query,
  request,
  type ParameterRequest,
} from '@ahoo-wang/fetcher-decorator';

interface User {
  id: string;
  name: string;
}

const client = new Fetcher({ baseURL: 'https://api.example.com' });

@api('/users', { fetcher: client })
class UserService {
  @get('/{id}', { resultExtractor: ResultExtractors.Json })
  find(
    @path('id') id: string,
    @query('expand') expand?: string,
    @attribute('requestId') requestId?: string,
    controller?: AbortController,
  ): Promise<User> {
    throw autoGeneratedError();
  }

  @post('', { resultExtractor: ResultExtractors.Json })
  create(
    @body() input: Pick<User, 'name'>,
    @request() override?: ParameterRequest,
  ): Promise<User> {
    throw autoGeneratedError();
  }
}
```

`@api` replaces every decorated method on its prototype chain with request
execution. Keep the placeholder body as `throw autoGeneratedError()` so an
undecorated call fails loudly. Instantiate and reuse the service; a new
`RequestExecutor` is not created on every call.

## Metadata merge and execution

| Item | Resolution |
| --- | --- |
| Path | class `basePath` + method `path`; a `ParameterRequest.path` replaces the method path. |
| Path/query/headers | Class values, then method values, then decorated arguments; per-call request is merged last. |
| Timeout, Fetcher, extractor | Method value first, then class value; a Decorator endpoint defaults to `JsonResultExtractor`. |
| Attributes | Class values, then method values, then `@attribute()` values. |
| Return type | Method `returnType`, then class `returnType`, then `EndpointReturnType.RESULT`. |

At invocation, arguments become a `FetchRequestInit`; `AbortSignal` and
`AbortController` arguments are recognized even without a parameter decorator.
The executor adds its target and metadata to `FetchExchange.attributes`, calls
`beforeExecute`, runs Fetcher's pipeline, calls `afterExecute`, then either
returns the exchange (`EndpointReturnType.EXCHANGE`) or the cached extracted
result (`RESULT`).

## Fetcher, cancellation, and lifecycle ownership

Fetcher resolution is endpoint `fetcher`, then class `fetcher`, then
`getFetcher(...)`'s registered named/default Fetcher. Keep Client setup outside
methods and reuse the service instance. `buildRequestExecutor()` caches one
executor per method **per instance**, and merges an instance's `apiMetadata`
only when it first creates that executor; set instance metadata before the
first endpoint call, not between calls.

```ts
import { Fetcher, ResultExtractors } from '@ahoo-wang/fetcher';
import {
  api,
  autoGeneratedError,
  get,
  path,
} from '@ahoo-wang/fetcher-decorator';

interface User {
  id: string;
}

const client = new Fetcher({ baseURL: 'https://api.example.test' });

@api('/users', { fetcher: client })
class UserService {
  @get('/{id}', { resultExtractor: ResultExtractors.Json })
  find(
    @path('id') id: string,
    controller?: AbortController,
  ): Promise<User> {
    throw autoGeneratedError();
  }
}

const service = new UserService();
const controller = new AbortController();
const user = await service.find('u-42', controller);
```

Implement `ExecuteLifeCycle` only for service-level hooks that need the
exchange. Put reusable HTTP concerns such as authentication, status handling,
and retries in Fetcher interceptors instead.

## Inheritance and common failures

`@api` walks the prototype chain and binds decorated inherited methods. Parameter
metadata uses copy-on-write, so redecorating a subclass parameter does not
mutate its parent metadata. A subclass should make an explicit decorator change
when it intentionally changes an inherited endpoint's request contract.

| Symptom | Check |
| --- | --- |
| Placeholder reaches the server | Use `@path('placeholder')`; minified inferred names cannot match the template. |
| Wrong client or base path | Check method metadata first, then class metadata, then the registered Fetcher name. |
| Result is unexpected JSON | Decorators default to `JsonResultExtractor`; specify `resultExtractor` for `Response`, text, or binary. |
| Cancellation does not stop I/O | Pass the actual `AbortSignal` or `AbortController` argument; `@request()` can also supply it. |
| Changed instance metadata has no effect | Its method executor was already cached; set metadata before first invocation or create a new instance. |
| Hook sees no response | `beforeExecute` runs before the Fetcher pipeline; use `afterExecute` for a successful response. |
