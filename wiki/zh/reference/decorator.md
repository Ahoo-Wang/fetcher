# `@ahoo-wang/fetcher-decorator`

Decorator 包把类和方法元数据转换为 Fetcher 请求。它适合希望以稳定服务接口替代各处
手工组装请求的团队。

## 安装

```bash
pnpm add @ahoo-wang/fetcher @ahoo-wang/fetcher-decorator reflect-metadata
```

在 TypeScript 中启用 `experimentalDecorators` 和 `emitDecoratorMetadata`，并在
应用启动时导入一次 `reflect-metadata`。

## 定义服务

```ts
import 'reflect-metadata';
import { ResultExtractors } from '@ahoo-wang/fetcher';
import {
  api,
  autoGeneratedError,
  body,
  get,
  path,
  post,
  query,
} from '@ahoo-wang/fetcher-decorator';

interface User {
  id: string;
  name: string;
}

@api('/users')
class UserService {
  @get('/{id}', { resultExtractor: ResultExtractors.Json })
  get(@path('id') id: string, @query('expand') expand?: string): Promise<User> {
    throw autoGeneratedError();
  }

  @post('', { resultExtractor: ResultExtractors.Json })
  create(@body() input: { name: string }): Promise<User> {
    throw autoGeneratedError();
  }
}
```

装饰后的方法会被请求执行逻辑替换。方法体只应抛出 `autoGeneratedError()`，让意外的
未装饰执行明确失败。

## 类与方法装饰器

| API                                   | 用途                             |
| ------------------------------------- | -------------------------------- |
| `api(path, metadata?)`                | 设置服务基础路径与共享请求元数据 |
| `endpoint(method?, path?, metadata?)` | 使用显式 HTTP 方法定义端点       |
| `get`、`post`、`put`、`patch`、`del`  | HTTP 方法快捷装饰器              |
| `head`、`options`                     | 元数据与能力请求                 |

DELETE 快捷装饰器名为 `del`，因为 `delete` 是 JavaScript 关键字。方法元数据会覆盖
同名类元数据。

## 参数装饰器

| API                | 参数映射目标                 |
| ------------------ | ---------------------------- |
| `path(name?)`      | URL 路径参数                 |
| `query(name?)`     | URL 查询参数                 |
| `header(name?)`    | 请求头                       |
| `body()`           | 请求体                       |
| `request()`        | 完整请求初始化对象           |
| `attribute(name?)` | 供拦截器使用的 exchange 属性 |

省略名称时使用反射得到的参数元数据。`path`、`query`、`header` 和 `attribute`
接收普通对象时，会展开其中的条目。

## 执行

`ExecuteLifeCycle` 描述装饰器请求生命周期。`EndpointReturnType` 可标注生成方法的
返回类型；工具需要检查配置时可使用 `ApiMetadata` / `EndpointMetadata`。

## Fetcher 解析

Decorator Executor 按以下顺序解析客户端：

1. 调用元数据提供的 Fetcher。
2. Endpoint 或 Class 元数据配置的客户端。
3. `fetcherRegistrar` 中的 `NamedFetcher`。
4. 默认注册的 `fetcher`。

多个服务共享认证、Base URL 或拦截器时使用命名客户端。不要在每个装饰方法中创建
新客户端。

## 返回值与取消契约

| 能力             | 契约                                                     |
| ---------------- | -------------------------------------------------------- |
| 返回类型         | 方法声明的 `Promise<T>` 描述提取结果，而不是原始响应     |
| Extractor        | Endpoint 元数据可以选择任意 Fetcher `ResultExtractor<T>` |
| `AbortSignal`    | Signal 或 Controller 参数会被识别并附加到请求            |
| Attributes       | `@attribute()` 值进入 `FetchExchange.attributes`         |
| Request override | `@request()` 为单次调用提供请求初始化                    |

`EndpointReturnType` 面向 Generator 和依赖反射的工具。普通服务应继续以 TypeScript
方法返回类型作为公共契约。

## 继承与生命周期

装饰子类会继承服务元数据。子类可以新增端点或覆盖元数据，但不应无提示地改变继承
方法的语义。生命周期 Hook 围绕请求创建和执行运行，只把无法放入 Fetcher 拦截器的
服务级行为放在这里。

缺少 `reflect-metadata` 或无法解析装饰参数时，请求会在 HTTP I/O 之前失败。把初始化
放在应用入口，让测试与生产加载同一套元数据运行时。
