# `@ahoo-wang/fetcher-decorator`

该包把 Class、Method 和 Parameter Metadata 转换为 Fetcher 请求。当稳定的服务接口比在每个调用处组装请求更清晰时使用它；动态请求形状则直接使用 `Fetcher`。

## 安装

```bash
pnpm add @ahoo-wang/fetcher @ahoo-wang/fetcher-decorator
```

启用 `experimentalDecorators`。该包自行导入 `reflect-metadata`；应用无需为这些 Decorator 额外在启动处导入它。

## Decorator 选择

| 需求 | API | 契约 |
| --- | --- | --- |
| 共享服务默认值 | `@api(basePath?, metadata?)` | Class Base Path、Headers、Timeout、Fetcher、Extractor、Attributes 与 Return Type。 |
| 显式 HTTP 方法 | `@endpoint(method?, path?, metadata?)` | Method 级 Endpoint Metadata。 |
| 常用 HTTP 方法 | `@get`、`@post`、`@put`、`@patch`、`@del`、`@head`、`@options` | `@endpoint` 快捷方式；`@del` 表示 DELETE。 |
| URL 参数 | `@path(name?)`、`@query(name?)` | 原始值使用参数名；对象会展开其条目。 |
| Header 或 Body | `@header(name?)`、`@body()` | Header 与 Path/Query 一致；Body 是唯一的请求 Body 值。 |
| 单次调用覆盖 | `@request()` | 接收 `ParameterRequest`，即带可选 `path` 的 `FetchRequestInit`。 |
| Interceptor 数据 | `@attribute(name?)` | 原始值、对象或 `Map` 写入 Exchange Attributes。 |

Path Placeholder 应显式指定名称。未命名参数由函数运行时文本推导，Minifier 可能重命名；当 `{placeholder}` 或 `:placeholder` 未绑定时，运行时会发出警告。

## 完整服务示例

```ts
import {
  Fetcher,
  ResultExtractors,
} from '@ahoo-wang/fetcher';
import {
  api,
  attribute,
  autoGeneratedError,
  body,
  get,
  path,
  post,
  query,
  request,
  type ParameterRequest,
} from '@ahoo-wang/fetcher-decorator';

interface User {
  id: string;
  name: string;
}

const client = new Fetcher({ baseURL: 'https://api.example.com' });

@api('/users', { fetcher: client })
class UserService {
  @get('/{id}', { resultExtractor: ResultExtractors.Json })
  find(
    @path('id') id: string,
    @query('expand') expand?: string,
    @attribute('requestId') requestId?: string,
    controller?: AbortController,
  ): Promise<User> {
    throw autoGeneratedError();
  }

  @post('', { resultExtractor: ResultExtractors.Json })
  create(
    @body() input: Pick<User, 'name'>,
    @request() override?: ParameterRequest,
  ): Promise<User> {
    throw autoGeneratedError();
  }
}
```

`@api` 会把 Prototype Chain 上每个已装饰的方法替换为请求执行。保留 `throw autoGeneratedError()` 作为占位方法体，让未装饰调用明确失败。实例化并复用 Service；每次调用不会创建新的 `RequestExecutor`。

## Metadata 合并与执行

| 项目 | 解析规则 |
| --- | --- |
| Path | Class `basePath` + Method `path`；`ParameterRequest.path` 替换 Method Path。 |
| Path/Query/Headers | Class 值、Method 值、已装饰参数；单次请求最后合并。 |
| Timeout、Fetcher、Extractor | Method 值优先，再取 Class 值；Decorator Endpoint 默认 `JsonResultExtractor`。 |
| Attributes | Class 值、Method 值、`@attribute()` 值。 |
| Return Type | Method `returnType`、Class `returnType`，最后为 `EndpointReturnType.RESULT`。 |

调用时，参数被转换为 `FetchRequestInit`；即使没有 Parameter Decorator，`AbortSignal` 和 `AbortController` 参数也会被识别。Executor 把 Target 与 Metadata 写入 `FetchExchange.attributes`，调用 `beforeExecute`，运行 Fetcher Pipeline，调用 `afterExecute`，再返回 Exchange（`EndpointReturnType.EXCHANGE`）或缓存的提取结果（`RESULT`）。

## Fetcher、取消与生命周期所有权

Fetcher 的解析顺序是 Endpoint `fetcher`、Class `fetcher`，再到 `getFetcher(...)` 的命名/默认 Fetcher。将 Client 配置放在方法外并复用 Service 实例。`buildRequestExecutor()` 每个实例、每个方法缓存一个 Executor，实例 `apiMetadata` 仅在首次创建该 Executor 时合并；请在首次调用 Endpoint 前设置实例 Metadata，而不是在调用之间修改。

```ts
const service = new UserService();
const controller = new AbortController();
const user = await service.find('u-42', 'team', 'req-9', controller);
```

只有需要访问 Exchange 的服务级 Hook 才实现 `ExecuteLifeCycle`。鉴权、状态处理、重试等可复用 HTTP 关注点应放入 Fetcher Interceptor。

## 继承与常见失败

`@api` 会遍历 Prototype Chain 并绑定已装饰的继承方法。Parameter Metadata 使用 copy-on-write，因此子类重新装饰参数不会修改父类 Metadata。子类有意改变继承 Endpoint 的请求契约时，应显式添加 Decorator 变更。

| 现象 | 检查项 |
| --- | --- |
| Placeholder 被发送到服务端 | 使用 `@path('placeholder')`；Minifier 推导出的名称无法匹配模板。 |
| Client 或 Base Path 错误 | 先检查 Method Metadata，再检查 Class Metadata，最后检查注册的 Fetcher 名称。 |
| 结果意外地成为 JSON | Decorator 默认 `JsonResultExtractor`；需要 `Response`、Text 或二进制时显式指定 `resultExtractor`。 |
| 取消未停止 I/O | 传入实际的 `AbortSignal` 或 `AbortController` 参数；`@request()` 也可以提供它。 |
| 修改实例 Metadata 没有效果 | Method Executor 已被缓存；首次调用前设置，或创建新实例。 |
| Hook 中没有 Response | `beforeExecute` 在 Fetcher Pipeline 前运行；成功响应请使用 `afterExecute`。 |
