# 保存与管理视图

## 保存实例配置

数据视图实例保存 `config.filters`、`sort`、`pagination` 和 `presentation`，其中 filters 保存组件属性。当前页/cursor、记录、选择、加载状态、错误、刷新倒计时和展开状态属于运行时。

修改筛选不立即查询；查询应用筛选，保存持久化已应用配置。有效的纯展示属性或新增未设置控件可以在查询不变时直接保存；会影响查询的待应用值必须先查询或撤销。重新打开时应恢复组件配置，再经数据源执行查询，不能把缓存记录反序列化后当作当前结果。

## 接入已实现的服务

`ViewHost.definition` 加载共享元数据；`instance` 负责实例的加载、列表、保存、创建、改名与删除；`preference.saveOrder` 保存当前用户顺序；`permission` 提供权限投影和变化通知。`resolveSource` 继续作为本地业务查询客户端的连接点。参阅[签名与返回值](../../reference/view-engine/view-host.md)。

保存、创建、改名后返回服务端确认的实例及新 `revision`。服务端必须检查所有权、权限与版本，UI 能力检查不能替代鉴权。创建通过 `ViewCreateContext.requestId` 支持幂等恢复。读请求可取消；界面生命周期结束不代表服务写入已回滚。

## 范围与权限

界面分为个人视图和公共视图两组。公共系统视图带“系统”标签，不允许改名或删除；公共共享视图按权限开放操作。点击编辑图标才进入名称输入，统一管理中还支持删除与排序。排序保存为当前用户偏好，也包括该用户看到的公共视图顺序。

权限初始化完成后才提供同步 getter。权限变化应通过 `permission.subscribe` 发布，或在同一范围内替换宿主/更新回调。切换用户、租户需要新的 `scopeKey`。

## 用 LocalStorageViewHost 开发验证

`LocalStorageViewHost` 是可执行的开发服务夹具，覆盖共享内容、个人所有权、用户顺序、版本和创建回执。必须显式提供 `storage`、共同使用的独占 `lock`、可信 `serviceKey` / `scopeKey`、定义与初始实例列表。它保存视图配置，业务记录数据源仍然独立。

在 **开发验证 → 本地视图恢复** 中保存、刷新并检查恢复；公开包的五类扩展示例也支持 `persistViews`。浏览器存储可被使用者修改，不能作为生产鉴权依据。`packages/view-engine/dev` 下的 HTTP 适配器属于实验，不是公开包导出，也不是已定稿的 REST 路由规范。

在 **专项场景 → 视图与运行时 → 视图管理**、**开发接入 → 业务扩展** 验证交互，服务验证脚本见 [ViewHost](../../reference/view-engine/view-host.md)。
