# fetcher v8.0.0-rc.1 release notes

The first release candidate of fetcher 8. Fetcher 8 is the line without CoSec:
the CoSec client and its React hooks moved to the CoSec repository and are
released with CoSec. Everything else behaves as in v6.1.0.

This is a prerelease, published under npm's `rc` tag. `latest` stays on
6.1.1 until 8.0.0, which is planned for the day CoSec 8.0 is generally
available. Install it explicitly:

```bash
pnpm add @ahoo-wang/fetcher@rc
```

The major version skips 7: fetcher 8 is released alongside CoSec 8.

## Breaking changes

- **`@ahoo-wang/fetcher-cosec` is not part of fetcher 8** (#2082). It is not
  published at 8.x. Its successor is `@ahoo-wang/cosec-fetcher` from the CoSec
  repository, which depends on the fetcher packages (CoSec → fetcher).
- **`@ahoo-wang/fetcher-react` no longer contains the CoSec hooks** (#2082):
  `SecurityProvider`, `SecurityContext`, `SecurityContextValue`,
  `SecurityContextOptions`, `useSecurityContext`, `useSecurity`,
  `UseSecurityOptions`, `UseSecurityReturn`, `ANONYMOUS_USER`, `RouteGuard`,
  `RouteGuardProps`, `RefreshableRouteGuard` and `RefreshableRouteGuardProps`.
  Their successor is `@ahoo-wang/cosec-react`. `@ahoo-wang/fetcher-react` no
  longer has a peer dependency on `@ahoo-wang/fetcher-cosec`; its other hooks
  are unchanged.

v6.1.1 (on the `6.x` branch) marked all of these `@deprecated`.

## Upgrade notes

| Your application                | Do this                                                                                                                                                                                                                                                                                                                      |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Uses no CoSec                   | Upgrade; nothing else changes.                                                                                                                                                                                                                                                                                               |
| Uses CoSec, server on CoSec 8   | Replace `@ahoo-wang/fetcher-cosec` with `@ahoo-wang/cosec-fetcher` (and the hooks with `@ahoo-wang/cosec-react`) following the [CoSec migration guide](https://fetcher.ahoo.me/guides/integrations/cosec), on the fetcher major their peer ranges accept; move to fetcher 8 once those ranges include it (from CoSec 8.0.0). |
| Uses CoSec, server on CoSec 7.x | Stay on fetcher 6.x. `@ahoo-wang/fetcher-cosec` 6.x keeps working against CoSec 7, and the `6.x` branch keeps receiving fixes.                                                                                                                                                                                               |

The old-to-new mapping of every export is in the CoSec documentation:
[cosec.ahoo.me/integration/clients](https://cosec.ahoo.me/integration/clients).
Until CoSec 8.0 GA, the CoSec packages are on npm's `rc` tag
(`pnpm add @ahoo-wang/cosec-fetcher@rc`).

**Peer ranges of the downstream packages.** At the time of this candidate the
CoSec packages (`8.0.0-rc.1`) declare `^6.1.1` for `@ahoo-wang/fetcher`,
`fetcher-eventbus` and `fetcher-storage`, and the Wow packages (9.9.0 and
10.0.0-beta.21) declare `^5.1.5 || ^6.0.0` for `fetcher`, `fetcher-decorator`
and `fetcher-eventstream`. Neither admits 8.x yet: an application that uses
them stays on fetcher 6.x until they widen their ranges (CoSec does so in
8.0.0); installing fetcher 8 next to them reports a peer-dependency conflict.

## Maintenance

- The release workflow checks, before building, that every package carries
  the same version, that it is lowercase semver (`8.0.0-rc.1`, not
  `8.0.0-RC1`), and that it matches the GitHub release's tag and pre-release
  flag. It publishes every package with an explicit npm dist-tag: a
  prerelease under its word (`rc`), never `latest`; a stable version under
  `latest`, or `latest-<major>` when npm's `latest` is already higher, so a
  6.x maintenance release cannot take `latest` back from 8.x. Before this, a
  prerelease could not be published at all (npm refuses one without `--tag`).
  Every npm lookup runs before the first package is published, so a failed
  lookup publishes nothing, and a package npm already has at this version is
  skipped, so rerunning a release that stopped part-way publishes the rest.
- The advisory `downstream-cosec.yml` runs CoSec's TypeScript against this
  repository's packed peers (#2084).
- Dependency updates: pnpm 10.34.9 (#2081), jsdom 30.1.3 (#2078), React
  19.3.1 for development (#2086), `@types/react` 19.3.2 (#2092),
  vitepress-mermaid-renderer 1.2.3 (#2089) and CI action pins (#2077, #2087).
