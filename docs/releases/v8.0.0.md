# fetcher v8.0.0 release notes

Fetcher 8 is the line without CoSec. The CoSec client and its React hooks
moved to the CoSec repository and are released with CoSec as
`@ahoo-wang/cosec-fetcher` and `@ahoo-wang/cosec-react`, which depend on the
fetcher packages. Apart from that, fetcher 8 behaves as fetcher 6.1: no other
public API changed, and the Node and React requirements are the same.

The major version skips 7: fetcher 8 is released alongside CoSec 8.

These notes are for readers coming from 6.x. **Coming from `8.0.0-rc.1`, no
action is needed**: 8.0.0 is the same code under a stable version.

## Breaking changes

- **`@ahoo-wang/fetcher-cosec` is not part of fetcher 8** (#2082). It is not
  published at 8.x. Its successor is `@ahoo-wang/cosec-fetcher`.
- **`@ahoo-wang/fetcher-react` no longer contains the CoSec hooks** (#2082):
  `SecurityProvider`, `SecurityContext`, `SecurityContextValue`,
  `SecurityContextOptions`, `useSecurityContext`, `useSecurity`,
  `UseSecurityOptions`, `UseSecurityReturn`, `ANONYMOUS_USER`, `RouteGuard`,
  `RouteGuardProps`, `RefreshableRouteGuard` and `RefreshableRouteGuardProps`.
  Their successor is `@ahoo-wang/cosec-react`. `@ahoo-wang/fetcher-react` no
  longer has a peer dependency on `@ahoo-wang/fetcher-cosec`; its other hooks
  are unchanged.

v6.1.1 marked all of these `@deprecated`.

## Upgrade

```bash
pnpm add @ahoo-wang/fetcher@^8.0.0
```

Upgrade every `@ahoo-wang/fetcher*` package you use to 8 together. Then
choose by whether you use CoSec and which CoSec version your server runs:

| Your application                | Do this                                                                                                                                                                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Uses no CoSec                   | Upgrade; nothing else changes.                                                                                                                                                                                                                                                              |
| Uses CoSec, server on CoSec 8   | Remove `@ahoo-wang/fetcher-cosec` and install `@ahoo-wang/cosec-fetcher@^8.0.0` (and `@ahoo-wang/cosec-react@^8.0.0` for React), following the [CoSec migration guide](https://fetcher.ahoo.me/guides/integrations/cosec). CoSec 8.0.0 and later accept fetcher 8 as well as fetcher 6.1.x. |
| Uses CoSec, server on CoSec 7.x | Stay on fetcher 6.x. `@ahoo-wang/fetcher-cosec` 6.x keeps working against CoSec 7.                                                                                                                                                                                                          |

The old-to-new mapping of every CoSec export is in the CoSec documentation:
[cosec.ahoo.me/integration/clients](https://cosec.ahoo.me/integration/clients).

**Wow.** The Wow packages (`@ahoo-wang/wow-*`) declare their own fetcher peer
range. Before moving an application that uses them to fetcher 8, check that
the range includes 8 (`npm view @ahoo-wang/wow-client peerDependencies`).

## 6.x stays maintained

The `6.x` branch keeps receiving fixes for applications on CoSec 7.x servers.
From this release, npm's `latest` tag points to 8.x and 6.x releases are
published under the `latest-6` dist-tag, so they never move `latest` back:

```bash
pnpm add @ahoo-wang/fetcher@latest-6
pnpm add @ahoo-wang/fetcher@^6.1.1   # equivalent, by range
```

`@ahoo-wang/fetcher-cosec` 6.x is deprecated on npm in favour of
`@ahoo-wang/cosec-fetcher`; it stays installable and keeps working with
fetcher 6.x and CoSec 7.

## Maintenance

- The release workflow checks, before building, that every package carries
  the same version, that it is lowercase semver (`8.0.0-rc.1`, not
  `8.0.0-RC1`), and that it matches the GitHub release's tag and pre-release
  flag. It publishes every package with an explicit npm dist-tag: a
  prerelease under its word (`rc`), never `latest`; a stable version under
  `latest`, or `latest-<major>` when npm's `latest` is already higher. Every
  npm lookup runs before the first package is published, packages npm already
  has at this version are skipped, and the run fails unless every planned
  package is accounted for (#2094).
- A CoSec migration guide in the documentation (#2093).
- The advisory `downstream-cosec.yml` runs CoSec's TypeScript against this
  repository's packed peers (#2084).
- Dependency updates: pnpm 10.34.9 (#2081), jsdom 30.1.3 (#2078), React
  19.3.1 for development (#2086), `@types/react` 19.3.2 (#2092),
  vitepress-mermaid-renderer 1.2.3 (#2089) and CI action pins (#2077, #2087).
