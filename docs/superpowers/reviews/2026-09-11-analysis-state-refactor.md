# 分析状态规则收敛验收

基于已确认的架构复审实施，基线为 be14b179；本轮不新增展示功能。

## 职责变化

| 规则                               | 原维护位置                                  | 本轮唯一决策位置                                               |
| ---------------------------------- | ------------------------------------------- | -------------------------------------------------------------- |
| 手动、打开、重载、自动刷新是否执行 | UI / 导航 / 执行器分别判断                  | analysisQueryPolicy；执行器仍保留信任边界校验                  |

| 采纳远端后丢弃本地输入             | 改 filterValid，编辑器生命周期未变化        | resetEditingSession 推进 editorEpoch，UI 按该代次重建编辑子树  |

## 行为契约

- manual：允许显式执行有效工作草稿，包括用户主动运行冲突中的本地分析；同一在途查询不重复提交。
- open：保留已有首次打开去重、取消首查后的重试和淘汰结果不自动重跑约定；不执行未解决冲突或待重载会话。
- reload：干净有效实例重新查询，本地修改/冲突不自动执行。
- auto：仅成功结果对应的同一查询、输入有效、写入空闲且没有冲突/待重载时刷新。公共 analysis(id).refresh() 与 React 自动刷新共用此策略。
- 展示配置错误仍阻止保存，但不改变查询本身的 queryValid；执行资格不再通过过滤错误消息 ID 推测。
- 普通 reload/restore 保留既有编辑缓冲语义；明确采纳远端才重置编辑生命周期。旧有效性回调被忽略，旧分析 edit、记录 edit/setFilterDraft 被拒绝。

## 回归与复审

查询策略有独立的无 UI 命令回归，以及打开/重载/取消/淘汰/冲突的动作序列。资源验证覆盖待核对另存会话、相同配置在不同预算下重新推导，以及宿主允许大于默认 256 KiB 配置时采纳远端仍刷新记录。后者通过暂时撤销预算传递再次失败、恢复后通过，避免把无效测试数据的错误当作资源回归证据。

编辑器覆盖记录与分析的实际本地输入、只改远端标题的采纳、普通重载/还原及旧回调；类型契约新增跨种类 result/config/instance/baseline 与变量形式的负例。运行时测试覆盖两类会话及 sessions/pendingCreates，错误 kind 不发布。

独立查询策略复审及整体静态复审未提出剩余可确认的新缺陷。复审中发现并修复了旧 record.edit 缺少 epoch 检查、自定义预算被默认预算覆盖的采纳分支、最终 validation 复用旧资源错误，以及命令构造时过早 assertReady 导致异步拒绝变成同步异常的问题。

## 范围与限制

初始化/rebase 工厂仍会准备编译结果，publication 是最终权威推导入口；这不是“所有操作全程只编译一次”的承诺。保留运行及写入边界再次验证，避免以去重为由削弱信任边界。

AnalysisEditor 仍是较大的 UI 组合组件；本轮通过移出自动查询规则、明确编辑生命周期减少职责耦合，没有把机械拆文件当作质量提升。共享重基线/另存转换仍有少量历史联合类型断言，不宣称所有内部断言已消除。后续应根据实际变化原因继续拆分，而不是新建通用状态机框架。

完整验证及最新 CI 结果在 PR 中按提交记录；静态审查和高覆盖率都不等于不存在缺陷。
