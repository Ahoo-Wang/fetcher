# 无兼容层统一方案：对抗性验证

日期：2026-09-10。对象：用户明确无需兼容后的一套 ViewEngine/定义/实例契约。结论：方向保持；发现 3 个规格闭环缺口，已在统一稿中修订。不是 3 个新运行缺陷，也不重新统计历史红测。

## 1. P1：修复草稿缺少明确生命周期

原规格把 ViewEntry 划分为 opening/ready/blocked/open-error，规定 query/write 状态只在 ready 会话内，blocked 没有可执行会话；另一方面，working 由分析会话持有，并承诺失效实例可编辑、切走后保留修复输入。

反例：打开缺失字段的分析实例，修复了一半后切走，再返回。若 blocked 只有原始文档和错误，没有持有 working 的编辑会话，修复内容没有恢复位置。进一步地，合法配置运行期间用户输入无效值，若立即将 ready 转为一个不同的 blocked 会话，还可能销毁已开始的有效请求与历史结果。

修订：加载生命周期与可执行性正交。ViewEntry 仅有 opening/loaded/open-error；loaded 对结构可解释、身份可信的文档始终建立编辑会话，持有 saved/working 及问题列表。blocked 是当前工作内容不能编译的展示状态，不是另一套需要重挂载的会话。编译成功才获得运行/保存候选。编辑暂时无效不撤销先前合法请求的所有权；返回结果依旧依据提交快照，当前编辑错误继续显示。

未知结构无法编辑时保持文档错误与宿主恢复入口，不能强断言为合法配置；也不要求先运行成功才能从修复状态保存。

## 2. P2：排序失败后不能局部修复

原规格仅给结果表头排序入口，又规定 working 查询身份不同于 result 时表头不可用。

反例：用户新增了有效维度/指标，已运行成功但尚未保存；随后点击指标排序，服务器因该排序执行成本等原因拒绝请求。working 含新排序，result 属于排序前口径，表头被禁用。用户只能重试失败请求或恢复更早的 saved，无法只撤销排序并保留刚完成的其他配置。

修订：配置区显式显示当前排序，提供修改和清除入口；修改只更新 working，不自动请求，用户再运行。表头是 working/result 一致时的快捷操作，不是排序状态唯一的编辑器。这样保留旧结果查询身份守卫，也提供局部恢复路径。

本项是产品规则反例，未声称任意后端都会拒绝某种具体排序；关键在于合法请求失败后仍能修复。

## 3. P2：结果时间的来源没有闭合到真实 API

证据：`packages/wow/src/query/queryApi.ts:44` 的 aggregate 返回 `Promise<Row[]>`，没有服务端执行时间或相对条件解析范围。原规格却把结果标注为执行时间，并举例“今天（9 月 10 日 23:59 运行）”。

反例：浏览器在 23:59:59 发出 TODAY 请求，服务器在次日实际执行；或浏览器时钟有偏差。请求时间不能证明统计范围是哪一天，响应时间也不等于服务端执行时间。把它们直接作为范围依据会制造错误的确定性。

修订：内置数据源记录本地请求发出与响应接收时间，UI 默认显示“结果接收于…”，注明时间来自当前设备；TODAY 等仍按原查询表达式与时区呈现，说明“相对时间按服务端执行时解析”。不将前端时间转换成声称已确认的绝对统计范围。若宿主提供可靠的服务端时间/解析范围，必须显式标明来源后才可显示；首版不新增此类后端接口，不用猜测补数据。

所有历史结果都标为某次请求的快照；恢复它不宣称数据最新。按既定产品选择由用户运行更新，具体后端时间语义仍需真实集成验证。

## 4. 未成立的猜测与应保留的约束

- 同一实例并发写入缺少互斥：当前 `InstanceWork.assertWritable` 已检查 write/reload/待核对状态，并由持久化/管理操作调用，不能报告为当前缺陷。统一规格补充明确操作矩阵，防止重构删掉这个约束。
- 只读用户没有还原入口：当前 `ViewInstanceActions.tsx:78` 在无保存/另存权限时仍可渲染“还原”，不能报告为当前缺陷。新 UI 必须保留本地恢复与服务器写权限的分离。
- 保存与运行独立必然产生冲突：该推断不成立。二者各自捕获 working 的不可变快照、各自持有令牌，结果与保存响应不互相写入，就可以独立推进。仍须在新实现中做真正的并发测试，不能仅靠设计声明验收。
- 取消兼容层后需要另建一套工作区引擎：不成立。统一 ViewEngine 与 kind 专属命令足以表达职责，保留第二套入口没有必要。

## 6. 收口条件

后续实施用例至少验证：失效文档修复一半切换后恢复；运行时输入变无效仍正确接收原请求；排序失败后仅清除排序而保留其他工作内容；时间文案不冒称服务端时间；同实例写互斥与跨实例并行；只读用户局部编辑/运行/恢复不触发持久化。

本轮针对明确反例收紧统一稿，不另建兼容层、缓存框架、通用状态机或额外数据服务。
