# Analysis implementation validation — 2026-09-10

## Implemented runtime and UI

- One `ViewEngine` owns immutable record/analysis sessions and shared persistence. Public business commands bind to an instance via `record(id)` / `analysis(id)`. `contracts`, `engine`, `record`, `analysis`, and shared `view` UI have explicit ownership; the two business modules do not import each other.
- `useViewEngine` owns React lifecycle and frozen compiler/editor registrations. `ViewPage` consumes the binding. Mixed navigation retains drafts, incomplete input, result snapshots and per-instance panel state.
- Saving valid working configuration does not query. Results and business renderers retain their executed query scope. Explicit conflict decisions use reviewed versions; uncertain writes preserve recovery state.
- Analysis compiles filters, grouping and metrics to a Wow aggregation query plus result schema. It validates result aliases, types, nulls and group uniqueness before atomic publication. Presentation order/width is applied without changing row identity.
- Bounded deadlines, query concurrency, retained results and configuration sizes are enforced. Metadata-only diagnostic events cover shared operations and record/analysis queries; observer failures are isolated.
- The mixed order story uses actual count/sum grouping over demo rows. Its pure-analysis variant exposes only `aggregate`. Charts, dashboards and a production backend deployment are outside this implementation.

## Public TypeScript artifact consumption — fixed 2026-09-11

The initial NodeNext check failed with 43 diagnostics. Wow and its dependency declarations contained extensionless relative references; suppressing those errors with `skipLibCheck` also hid lost query type constraints. This was a declaration resolution defect, not a failed runtime aggregation.

The source imports/exports in `fetcher`, `eventbus`, `storage`, `cosec`, `decorator`, `eventstream`, `wow` and `react` now use explicit `.js` paths and `/index.js` for directory references. Declaration generation preserves these valid paths. No generated declaration was hand-edited; no dependency, public signature, package export map or build configuration was changed.

Verified with TypeScript 6.0.3:

- Wow public root and both locale exports resolve under NodeNext with `strict: true` and `skipLibCheck: false`. Negative probes reject empty aggregation metrics and an invalid QueryApi value.
- Packed View Engine core and React exports resolve under NodeNext with strict declaration checking. The headless consumer also passes without DOM declarations. Negative probes reject empty metrics and a missing engine scope.
- The existing packed Bundler checks still verify immutable inputs/renderers and 18 React example modules.

After the fix, `VITEST_MAX_WORKERS=4 pnpm test:unit` passed, as did the dependency builds and packed consumer check. A syntax-tree comparison of all 146 affected dependency source files found no semantic changes beyond relative module references. Affected-source ESLint reported zero errors and retained existing warnings (mostly explicit `any`); the package verifier lint and `git diff --check` passed.

These checks use public package exports and built declarations, not private source aliases. They verify Wow and the View Engine dependency chain, not unrelated package entry points throughout the monorepo.
