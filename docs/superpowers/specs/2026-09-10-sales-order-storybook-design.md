# View Engine Storybook：销售订单全链路

日期：2026-09-10

状态：用户已确认设计；实现与验证完成，改动保留在当前 worktree，未提交。

## 1. 目标与范围

以虚构的企业办公设备销售商为背景，让开发者体验同一批销售订单从创建、审核、收款放行、备货交付、对账结算到售后关闭的过程。业务规则是本演示明确选取的一套约定，不代表所有行业或企业的制度。

成功标准：开发者既能亲手完成一笔订单，又能定位某个业务阶段，理解 ViewDefinition、ViewInstance、ViewHost 与运行时扩展如何配合，并找到可复用的实际源码。

采用“全链路订单工作台 + 业务章节 + 专项场景”。主线围绕订单工作任务，技术能力在对应任务中展示。专项场景允许继续使用商品、基础字段等更适合解释该功能的语境。

本次实现范围是 Storybook、被故事引用的示例及其测试。复用公开 API，不增加业务逻辑到引擎核心，不新增依赖，不修改构建配置。导航排序属于故事组织范围。订单业务宿主为每次挂载隔离的内存演示服务；不接真实支付、物流、税务或仓储服务。

## 2. 已核对的实现基础

- 当前仓库与 view-engine 版本均为 5.0.0；Node >=20.20.2，pnpm 10.34.5。
- 公开 ViewInstance 当前支持 record；布局支持 table/card。主线不宣称引擎具有分析图表、看板拖拽或 Dashboard 实例能力。
- ViewHost 分离 definition、instance、preference、permission 与 resolveSource；可用同一页面接入本地定义或服务加载定义。
- ViewExtensions 提供 filters、cells、globalActions、toolbarActions、rowActions；renderCard、renderToolbar、renderPagination 是组件渲染接入点，应与可序列化的扩展引用区分。
- record-view 已有较完整的订单快照、查询、汇总和视图保存宿主。examples/react 的另一套订单只有 pending/processed，两套模型不能直接作为同一条全链路使用。
- 现有 OrderOperations 已分离写入成功和刷新成功，可复用其“刷新失败不重复写入”的处理方式。

## 3. 信息架构与初次体验

View Engine 导航顺序：

1. 全链路体验：完成一笔销售订单。
2. 接单与审核：核对订单；驳回后修改重提。
3. 收款与放行：预付款放行；账期订单放行。
4. 备货与交付：缺货跟进；分批发货；签收与拒收。
5. 对账与结算：核对收款与开票；完成结算。
6. 售后与关闭：部分退货退款；取消订单；关闭订单。
7. 我的工作视图：保存与恢复；共享与权限；表格与卡片配置。
8. 扩展接入：业务筛选、展示与操作；区域定制；本地与服务定义。
9. 专项场景：基础控件、操作符、主题、异常、游标等。

“开发验证”继续容纳性能数据、本地持久化和 HTTP 实验，不混入主线。

每个展示故事提供简短的角色、待办目标、操作提示及预期结果。例如：“你是交付专员。远航科技的订单已备齐 6 台，先发出这批，剩余 4 台继续跟进。”不在业务工具栏展示查询次数、JSON、注册名称等实现信息。

默认先看到订单工作区；Docs 展示业务前情、能力映射和真实源码。开发诊断折叠展示查询条件、保存配置、操作记录。展示故事保留可操作的初始状态，自动 play 流程放入独立回归故事，避免打开文档时订单已被自动处理。

全链路故事提供“重置演示”。岗位切换共享本次挂载的订单存储，订单查询重新加载；章节故事使用相同模型及明确的阶段种子独立初始化，不依赖访问顺序。刷新浏览器默认重置业务数据；持久化专项只明确验证其声明的视图配置恢复范围。

## 4. 业务模型与不变量

订单继续使用 MaterializedSnapshot 形状：aggregateId 标识订单，state 保存业务字段。业务 ID 与显示名称分离。时间采用毫秒时间戳，展示时区 Asia/Shanghai；演示时钟固定为 2026-09-10 10:00，交期和账期样本相对此时钟计算，避免故事过期失效。

订单包含客户、负责人、区域、结算方式、交期、应收到期日、订单明细及收款、发货、签收、退货、退款、开票记录。详情展示这些记录与操作时间线。采用固定 SKU 和客户目录，不建设独立主数据管理系统。

区分以下维度，禁止用一个“处理中”代替：

- 订单：草稿、待审核、已驳回、已确认、已取消、已关闭。
- 收款：未收款、部分收款、已收齐；同时展示已退款、待退款金额。
- 履约：未发货、部分发货、已发货；另外展示待签收、已签收、拒收待处理数量。
- 开票：未开票、部分开票、已开齐；有退货时展示待冲减金额。
- 售后：无售后、退货处理中、待退款、已完成。

状态由已记录的业务事实推导，避免独立修改标签造成数量与状态矛盾。主生命周期状态通过业务动作转移。

金额在业务运算中使用整数分；查询快照提供人民币元数值供既有 NumberCell 与汇总使用。单价输入最多两位小数，数量为正整数。本演示无折扣、运费、多币种与税额拆分，含税单价就是结算单价。

- 原订单金额 = 各行单价 × 订购数量之和。
- 有效应收 = 原订单金额 − 已接受退货金额；整单取消后为零。
- 净收款 = 累计收款 − 累计退款。
- 待收款 = max(有效应收 − 净收款, 0)。
- 待退款 = max(净收款 − 有效应收, 0)。
- 净开票 = 累计开票 − 累计冲减；待开票和待冲减分别取与有效应收差额的正值。
- 已签收 + 拒收待处理 <= 已发货；已接受退货 <= 已签收。
- 发货以尚未发出的备货数量为上限；拒收商品登记回仓后，该数量重新进入待交付，可再次备货发货，历史发货记录保留。
- 退款不得超过待退款；普通收款不得超过待收款。所有数量、金额及岗位约束在宿主写入前校验，不能只依赖按钮禁用。

## 5. 操作规则

| 动作      | 前置条件与输入                                                                                   | 可见结果                                                 |
| --------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 创建/修改 | 客户、商品、数量、单价、交期、结算方式完整；只允许草稿或驳回订单修改                             | 生成明确金额的草稿；修改后重新提交审核                   |
| 提交/审核 | 销售提交；主管审核，驳回必须填写原因                                                             | 进入待审核、已确认或已驳回；详情保留原因                 |
| 收款      | 财务录入金额、凭证号；已确认且存在待收款                                                         | 收款记录和余额更新；部分收款不会错误标记已收齐           |
| 放行      | 预付款订单要求收齐；账期订单要求演示客户的账期授权有效、无逾期欠款                               | 写入放行事实，订单进入交付待办；账期订单可先履约后收款   |
| 备货/发货 | 已放行；逐商品填写本次数量；发货填写运单                                                         | 可部分备货、部分发货；剩余数量继续保留在待办             |
| 签收/拒收 | 基于指定发货记录，数量不得超过本次待签收数量                                                     | 明细数量更新；拒收进入异常待办，登记回仓后允许重发       |
| 开票/冲减 | 已确认；填写金额和凭证；不得超过待开票/待冲减金额                                                | 形成独立开票记录；可与收款、履约交错进行                 |
| 退货      | 已签收商品可申请；客服审核后按实际收货数量登记接受退货                                           | 有效应收减少；产生待退款或减少待收款；已开票则产生待冲减 |
| 退款      | 财务基于待退款登记金额与凭证                                                                     | 余额更新；刷新失败后只重试读取                           |
| 取消      | 草稿、驳回、待审核或已确认但尚未发货；已收款需后续退款，已开票需冲减                             | 停止履约；取消状态仍可完成资金与票据善后                 |
| 结算核对  | 财务核对金额与记录；无待收、待退、待开票或待冲减                                                 | 记录已核对；后续退货等金额变化使该核对失效               |
| 关闭      | 正常订单全部完成签收或后续退货，无交付异常和开放售后，且完成结算核对；取消订单完成财务善后及核对 | 订单只读，保留全程记录；演示不提供关闭后重开             |

批量动作选择审核通过与放行两项，不把创建、退款或发货简化成无输入的批处理。宿主先校验全部选中订单再统一应用；任一不满足条件则全部不写入，展示具体订单与原因。混合有效/无效订单有专项回归。

岗位包含销售、销售主管、交付专员、财务和客服。岗位切换是演示宿主的权限模拟，业务写入仍验证岗位；ViewHost.permission 仅用于视图保存、共享等能力，不宣称其提供业务权限或后端数据隔离。所有岗位可查看同一批演示订单。

## 6. 样本与完整旅程

所有订单使用同一个虚构销售商、客户目录和办公设备商品目录。主线提供至少 18 笔具名订单，保证分页、筛选及本页/全部汇总可观察，不靠重复复制数据填充。

核心锚点如下；其余样本覆盖不同客户、负责人、交期和金额。

| 订单/客户               | 初始业务事实                                                 | 要展示的判断                                           |
| ----------------------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| 新建订单/启明设计       | 用户选择显示器 2 台，每台 1,200 元，总额 2,400 元            | 创建→审核→全额预付→放行→发货→签收→开票→核对→关闭       |
| SO-202609-1001/远航科技 | 10 台显示器，合计 12,000 元，已付清，已备货 6 台             | 发出 6 台仍有 4 台待交付；分批记录可追踪               |
| SO-202609-1002/澄明咨询 | 账期订单 6,000 元，账期授权有效、无逾期，未收款              | 放行与交付后再收款，不能被预付款规则阻塞               |
| SO-202609-1003/星河教育 | 总额 8,000 元，预付 3,000 元                                 | 尚差 5,000 元，不可放行                                |
| SO-202609-1004/青禾制造 | 已到交期，仍缺货 2 台                                        | 交期风险筛选和按交期排序                               |
| SO-202609-1005/云杉传媒 | 已收齐并开票 4,800 元，签收 4 台，退回其中 1 台价值 1,200 元 | 有效应收 3,600 元，退款和票据冲减各 1,200 元后核对关闭 |
| SO-202609-1006/明川贸易 | 未发货，已收 2,000 元，随后取消                              | 取消后仍需退款，不能直接关闭                           |
| SO-202609-1007/知行工程 | 发货 5 台，签收 4 台，拒收 1 台                              | 拒收→回仓→重新发货→签收，保留历次记录                  |

跨阶段联动验收：放行后同一订单出现在交付待办；部分发货后保留未交付数量；收齐后退出待收款视图；接受退货后进入退款/冲减待办；处理完成后才满足关闭条件。

## 7. 能力展示映射

| 能力               | 业务落点与验证                                                                          |
| ------------------ | --------------------------------------------------------------------------------------- |
| 简单与高级筛选     | 查找本人待审核、逾期未交付；AND/OR 保存再打开不改变含义                                 |
| 远程候选           | 搜索客户与负责人，保存使用 ID，重开回填名称，分页失败可重试                             |
| 数组同元素匹配     | 找到“同一条明细为显示器且数量 >=5”的订单，设置反例避免跨商品误命中                      |
| 排序、分页、列配置 | 交期优先，固定订单编号/操作列，调整金额列与可见列；游标留在专项                         |
| 本页与全部汇总     | 当前筛选下订单金额、净收款、待收款；翻页只改变本页汇总                                  |
| 表格与卡片         | 财务用表格对账，交付用订单卡片查看客户、交期和履约进度；不强加商品封面                  |
| 视图管理           | 系统预置各岗位待办；另存个人视图、共享团队视图、改名排序删除及恢复未保存修改            |
| 自定义筛选         | “交期风险”保存用户配置，编译到已有字段条件；空值、清空、重新打开语义一致                |
| 自定义单元格       | 履约进度、回款进度；纯展示，状态来自只读快照                                            |
| 全局/工具栏/行操作 | 创建订单；批量审核/放行；订单详情与阶段操作，成功后调用绑定视图的 refresh               |
| 区域扩展           | 包装默认工具栏加入“交付关注说明”，自定义订单卡片突出剩余数量；保留原选择及动作语义      |
| 本地与服务接入     | 同一订单定义可本地提供或通过 ViewHost 加载；服务加载主线用内存异步模拟，不伪装真实 HTTP |
| 主题与响应式       | 订单工作台验证明暗主题、窄屏、弹层和键盘；完整主题矩阵留在专项                          |

筛选、视图配置和业务写入分别表达：修改筛选草稿不自动改结果；点击查询才应用。保存视图不保存订单业务数据。切换表格/卡片不改变查询含义。

## 8. 实现边界与复用

统一业务模型、种子、查询宿主和订单动作，供完整工作台与章节复用。以现有 record-view 查询和视图管理宿主为基础，检查调用者后改造；不再维护第三套通用查询解释器。仅支持定义声明的操作符，未知输入明确报错。

一个场景运行时持有订单存储和岗位；ViewHost 查询与业务动作读取同一存储。订单详情与操作表单属于示例业务 UI，使用现有组件。用普通类型和函数组织动作校验，不引入通用工作流引擎、状态机依赖或业务插件框架。

现有最小接入代码仍保持易复制，但改用统一订单语义；不要求最小示例挂载全部业务流程。examples/react 若被 wiki 或测试复用，先迁移所有调用者，再删除旧 pending/processed 示例。代码面板必须指向实际渲染源码，不能展示过期简化代码。

故事迁移逐项保留既有测试意图，删除重复展示入口。商品卡片保留为“封面与自定义卡片”专项；日期精度、50 种操作符、安全链接、错误数据、HTTP 实验继续独立。Overview 及其他故事链接随新 ID 更新，保持 verify-storybook 的实验隔离和回归索引要求。

## 9. 失败与恢复

- 查询失败保留上次结果，明确“刷新失败”；首次失败与成功空结果分别展示。
- 写入前失败不改变订单，可重试；写入成功但刷新失败明确提示“操作已完成，列表未刷新”，仅重试查询。
- 防止重复点击；金额和数量写入使用请求标识去重，同标识不同内容拒绝，失败前不记录成功回执。
- 操作发生岗位/视图切换时，已发出的动作保留发起上下文，刷新绑定原实例；后续动作重新校验当前岗位。
- 汇总失败不抹去订单数据，本页汇总与全部汇总错误独立。
- 视图版本冲突保留草稿并引导重新加载，不自动覆盖服务配置。
- 不允许把失败当作成功空列表，也不通过直接修改 readonly record 更新界面。

## 10. 验收与验证

业务宿主测试使用现有 Vitest：验证金额/数量不变量、放行两条路径、混合批量原子性、退货退款/冲减、取消善后、拒收重发、关闭约束、非法岗位和重复请求。围绕真实旅程断言状态与余额，不为每个字段机械添加测试。

Storybook 浏览器回归覆盖：

1. 从表单创建 2,400 元订单，完成预付全链路，并从详情确认所有记录与关闭状态。
2. 账期订单未收款时可以合法交付，最终补齐收款并结算。
3. 分批发货前后数量、待办归属及汇总正确。
4. 部分退货后退款与冲减数值正确，未完成善后无法关闭。
5. 筛选草稿、手动查询、另存与重新打开、自定义配置、表格/卡片往返保持含义。
6. 写入成功刷新失败后重试不会产生第二笔收款/发货；视图切换不刷新错误实例。
7. 主线故事独立挂载、重置后结果一致，不相互污染；公开故事无自动推进。

视觉与可访问性检查实际浏览器的桌面/窄屏、明暗主题、弹层边界、键盘焦点、禁用原因和反馈播报。主入口及交付、财务、售后三个章节截图人工检查。
