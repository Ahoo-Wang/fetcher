本文件细化总体架构，锁定接口、时序、恢复、资源和验收要求，不增加兼容层或第二套引擎。总体边界见 `2026-09-10-view-engine-overall-architecture.md`；分析交互细节见重设计稿。生产源码与发布版本本轮均未修改。

## 1. 可以保证什么

库负责同一引擎访问范围内的可恢复编辑、正确请求归属、原子状态、实例级错误隔离、明确的写入确认与 UI 反馈。宿主负责真实认证/授权、持久化原子性、创建幂等、服务端资源限制及后台数据语义。

类型检查证明调用形状，不证明服务器安全、时序正确或统计正确。CAS 防止使用旧版本直接覆盖，不能替代冲突决策。Abort 结束本地请求意图，不证明服务器业务已经停止。行数组不能证明服务端执行时间、总分组数或截断标志。

跨页面刷新/关闭后的未保存草稿不是默认持久化承诺。需要跨重启恢复未知写入的宿主必须在派发前持久保存 requestId、提交摘要/必要正文、访问范围及恢复信息，并提供核对入口；不能仅依赖引擎内存后宣称 exactly-once。宿主使用此能力时需要单独验证隔离、保留期限与清理策略。首版库不自行引入离线队列或自动持久化所有敏感编辑内容。

## 2. 可检查的公共接口契约

接口样例位于 `assets/view-engine/production-contract.ts`，消费探针位于 `production-contract.examples.ts`。它们仅是设计资产，不从包导出、不实现引擎。复用当前纯过滤与记录展示类型以及 Wow 查询接口来约束真实形状；具体字段语义仍需运行验证。

主要决定：

- ViewEngine 仅公开加载/选择、共享实例操作、快照订阅和类型命令入口。
- `record(id)` 与 `analysis(id)` 返回绑定身份与会话代次的命令对象，运行时再次检查类型与生命期。纯分析不能调用分页。
- 类型命令的 `edit(updater)` 接收当前只读 working，返回新 working。回调必须同步且纯；异常不提交任何变化，不能重入执行副作用。UI 使用字段/组件 ID 的具体编辑函数调用此入口，不持有可写 Store。
- ViewHost 必须能加载定义、实例列表、指定实例及权限；本地宿主用内存/本地存储实现同样的读取契约。缺少写方法意味着相应能力不可用。
- 服务器文档的 revision 必填，创建输入不带 id/revision，且不能创建 system 范围；本地模板也必须获得稳定基线 revision，不能伪造允许绕过 CAS 的空版本。
- CreateInput 保留 kind/config 的判别关系；ViewSource 至少具备 paged/cursor/aggregate 一种能力。
- 权限是带单调 revision 的完整投影，实例中缺失的授权项按拒绝处理。宿主订阅交付新快照，引擎忽略迟到旧 revision；同 revision 不得对应不同内容。
- `saveAs` 成功返回新 instanceId，即使用户已经离开原实例，也能明确获得创建结果，不通过当前选择倒推新身份。

记录、分析会话的结果结构不同；每份记录结果也携带实际请求范围，不能仅有 rows 和 queryKey，业务操作不得根据当前 working 猜测范围。

## 3. 命令结果和异常

异步命令成功返回 completed；尚未派发的取消或有效读取消返回 cancelled；被新意图替代返回 superseded。业务/契约/权限/超时失败拒绝 Promise，同时原子发布归属实例的结构化错误。取消与 superseded 不显示成用户错误。

已经派发的写请求遇到超时、断连或取消，不返回“已取消且未生效”，必须进入 unknown 并要求核对。明确的服务拒绝进入 rejected，确认成功进入 succeeded。WriteAttempt 保存原 submitted、requestId 与 operationId，未知结果不会因为切换实例或某次重试明确失败而自动被清除。

沿用 ViewServiceError 的稳定业务分类，并为客户端补充配置无效、响应契约错误、超时、资源超限与忙碌等分类。UI 依据 code/action 状态提供恢复入口，不解析自然语言错误字符串。详细内部异常交给诊断通道，用户错误信息不包含凭据、原始响应正文或堆栈。

旧绑定命令在 scope 更换、实例删除/重建或引擎销毁后明确拒绝；不能落到同 ID 的新会话。disposed 引擎不再发布可变状态，dispose 幂等。

## 4. 原子操作协议

每次命令遵循：检查 → 登记所有权并捕获输入 → 发布开始状态 → 外部调用 → 核验所有权与响应 → 一次提交终态 → 通知订阅。

应用层持有令牌/AbortController 登记；Store 持有可观察事实，二者不是相互独立可写的业务镜像。结束登记必须在终态通知允许重入命令之前完成；通知中的新命令不能被旧 finally 清掉。任何会调用宿主、abort listener 或外部观察者的步骤后重新核对操作身份。

每次 Store 提交递增快照 version；工作编辑单独递增 editVersion。保存返回只替换 saved 与写终态，不改变之后的 working。冲突面板操作同时携带展示过的 remoteRevision 与 editVersion；任一已变化则更新面板并要求重新选择，避免覆盖用户未审阅的新内容。

同实例保存/另存/重命名/删除/远端重载互斥，不提供无界隐式操作队列；忙碌时命令返回可解释错误。不同实例允许并行。普通查询与保存并行，但删除/访问范围变化会失效相应查询；回包不会复活实例。

订阅回调和诊断回调异常不影响已提交状态或其他订阅者。查询/写入模块不能直接调用对方的内部 patch。pure updater 内部不允许调用其他引擎命令；类型声明和运行时提交守卫共同约束。

## 5. 宿主写入和恢复契约

| 操作      | 服务器最低保证                                                                        | 客户端核对                                         |
| --------- | ------------------------------------------------------------------------------------- | -------------------------------------------------- |
| save      | 身份/归属不可改变；按 revision 原子条件写；返回新文档                                 | 身份、kind、定义、提交内容及新 revision            |
| create    | 在访问范围内原子登记 requestId/正文与创建回执；同键同正文返回原结果，同键不同正文拒绝 | 新身份、原提交内容与归属；重试复用原 requestId     |
| rename    | 只修改名称，CAS，配置保持不变                                                         | 名称之外的内容不能被服务悄悄改写                   |
| delete    | CAS；重复执行与不存在行为明确，不越权泄露其他用户实例                                 | 删除确认后清理正常会话，但保留已有未知创建恢复信息 |
| saveOrder | 只写用户偏好，验证可见实例范围；不改变实例文档                                        | 顺序响应不能删除新实例或复活已删除实例             |

WriteContext 的 requestId 对 create 是强制幂等键，对其他操作至少是诊断关联标识；不能据此声称所有后端写都自动具备幂等回执。read/list 必须返回当前可见范围内的权威事实，不能按同名实例猜测未知创建的身份。

读取不存在或收到一次明确拒绝不必然证明更早超时写未生效。未知 create 按原 requestId 重放或由宿主提供可靠回执；未知普通写按原提交与权威内容核对。当前权限不足以重放时保持待核对状态，给宿主恢复入口，不另建一个可能重复的逻辑创建。

记录 baseline/local/remote 的内容比较按明确的可编辑字段进行，排除 revision、服务器身份。结构上相同不等于共享对象引用；排序无关的对象键不应制造假冲突，数组顺序仍有语义。首版不实现通用字段级自动合并。

LocalStorageViewHost 是有明确访问范围的本地适配器与契约样例。其锁域覆盖同一存储键所有参与方；不同标签页验证使用同一 Web Locks 域或等价宿主原子机制，不能用一个标签页的 JS mutex 声称跨标签页 CAS。测试替身不能代替远程服务的事务证据。

## 6. 权限与输入边界

客户端能力 = 已验证身份/归属、定义允许能力、权限投影和宿主实现方法的交集；系统范围进一步禁止原地覆盖/删除/重命名。所有写入在执行时复核，不只看渲染时按钮状态。服务器仍做最终授权。

工作内容只允许编辑 title/config，id、definitionId、kind、scope 与 revision 由生命周期协议控制。另存是改变归属的明确操作，不能通过编辑回调修改身份。缺失组件或字段失效属于可修复语义问题，不跳过身份/归属校验。

任意配置与服务回包都执行运行时校验；编译器注册是受信代码扩展，不把不受信 JSON 当代码执行。组件 props/options 只保存允许的 JSON 值，拒绝函数、循环引用及非有限数值等非法传输内容；无效的原始文本仍可以字符串作为编辑数据保留。

宿主明确通知访问范围撤销时销毁旧引擎；新权限快照不允许旧响应恢复写权限。宿主明确分类的读取授权失败使相应数据不可再展示。库不能自动发现服务器未通知的权限变化，因此不承诺浏览器缓存替代实时授权。

## 7. 资源预算与退化

以下为初始可配置预算，属于设计默认值，不是已测得的性能：loadTimeoutMs=15000、queryTimeoutMs=30000、writeTimeoutMs=30000、maxConcurrentQueries=4、maxRetainedResults=5、maxConfigBytes=262144。参数需正数/安全整数等运行校验，宿主可依据真实服务调整。

超时覆盖一次逻辑操作的外部等待，包括数据源解析。引擎本地结束等待并失效令牌，即使宿主未及时响应 abort，迟到响应也不提交；写超时按 unknown 处理。适配器必须尽量尊重取消，但这些限制不保证服务器已经停止计算。

并发上限限制引擎仍拥有的活跃读操作；超额时明确忙碌，不无限排队或自动重试。应用层不会在权限失败、配置失败或组件错误时循环重试。

结果保留采用有限的非当前实例淘汰策略：超限时先丢最近最少访问的非当前 result，保留 saved/working/校验与未决写入。只有必要时采用小型既有集合记录访问顺序，不引入缓存依赖。当前结果不被静默替换，用户返回已淘汰结果的实例时看到“请重新运行”。外部代码持有旧快照造成的内存占用不在引擎可强制释放范围内。

maxConfigBytes 检查序列化的 UTF-8 长度，超限保留可恢复编辑并阻止外部写/运行，不默默截断。过滤深度、节点数和聚合维度/指标/排序/行数依照实际协议限制验证，不能只限制数组最外层。

适配器或服务器负责响应体/传输体上限；返回 Row[] 后再做检查不能防止解码阶段大响应占用。上线消费应用必须配置并验证该上限，本库不把“已验证行数”宣传为完整内存隔离。

初始性能验收目标：代表性环境、100 行默认结果、100 个字段与 20 个过滤项下，本地输入提交 P95 ≤50ms；纯本地实例切换 P95 ≤100ms，不包含网络时间。必须记录设备、浏览器、样本量、数据规模及 production build。1万行/多列压力场景单独验证不丢输入和可取消性，不能把小数据指标外推。默认预算未达标则优化数据复制/订阅范围或收紧默认规模，不能用延迟丢弃输入达标。

## 8. 可观测性

可选 onDiagnostic 接收 operationId、kind、operation、phase、elapsedMs、errorCode。默认不发送网络请求、不记录 filter/props/rows、业务标题、凭据、身份范围或用户数据。宿主可在明确权限与日志策略下关联其服务日志。

耗时使用单调时钟；结果展示使用设备时间并标明来源。每个本地操作只产生一个终态事件，superseded/cancelled 与失败分开统计。观察者抛错隔离，不改变命令成功/失败。诊断不成为命令通信总线。

宿主至少能够区分配置阻断、响应契约错误、服务失败、超时、取消、旧回包忽略、版本冲突和未知结果。生产支持应能用 operationId 找到对应路径，而无需输出整份敏感查询。

## 9. UI 验收与故障演练

头部显示保存状态，配置区显示输入问题，结果区显示请求状态和来源；只读用户的临时修改不要求保存。正在打开目标或加载失败时不能操作旧实例。修复状态保留工作输入和焦点，不重建整个页面。

必须通过键盘完成导航、输入、排序、运行、保存、冲突与修复；焦点可见，弹层关闭回到正确触发点，异步返回不抢焦点。窄容器、200% 缩放、长标题、多语言和深浅主题下无关键控件遮挡。真实浏览器检查不能由 jsdom 替代。

演练包括：断网/超时后保存核对、同一实例多标签页 CAS、慢请求 A→B→A、保存中编辑、配置更新/权限撤销、失效实例修复、未知组件、排序失败、取消后迟到响应、StrictMode 重挂载，以及日志不泄露配置正文。

复现类型检查：

```sh
pnpm --filter @ahoo-wang/fetcher-view-engine exec tsc \
  --ignoreConfig --noEmit --strict --exactOptionalPropertyTypes \
  --skipLibCheck --module ESNext --moduleResolution Bundler --target ES2022 \
  "$PWD/docs/superpowers/specs/assets/view-engine/production-contract.examples.ts"
```

skipLibCheck 只跳过依赖声明内部检查，因此这一通过不能证明所有依赖声明本身正确，更不能替代最终 tarball 消费验证。探针中的 @ts-expect-error 必须被真实错误消费；若非法调用被放行，编译应因未使用的指令失败。
