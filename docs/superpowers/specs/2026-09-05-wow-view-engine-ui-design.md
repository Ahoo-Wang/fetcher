# Wow 视图引擎 UX 方向与组件设计原则

日期：2026-09-05。布局方向采用用户确认的“2 + 1，2 收缩后显示 1”。效果图只作为整体 UX 方向，单个组件结合实际业务任务打磨；图片不冻结按钮主次、尺寸、列数或示例数据。交互尚未实现，数据、业务操作和保存语义遵循 [视图引擎设计](2026-09-05-wow-view-engine-design.md)。

| 视图          | 用户任务                         | 交互重心                                     |
| ------------- | -------------------------------- | -------------------------------------------- |
| RecordView    | 业务人员找到并处理实际业务记录   | 筛选定位、全局业务操作、行操作、处理结果反馈 |
| AnalysisView  | 明确统计口径，比较并解读业务数据 | 筛选、维度、指标、聚合结果及进一步查询       |
| DashboardView | 观察整体情况，发现需要关注的问题 | 关键指标、关联面板、全局条件、进入相关视图   |

三类视图共用实例管理能力，各自组织任务操作。业务处理、查询查看与视图配置保存分别表达。已有图片尚未完整展示全局业务操作，组件实现不能因图中没有某个入口而省略已确认能力。

## 1. 同一页面的展开与收起

![记录视图：展开导航与收起导航](assets/wow-view-engine/record-navigation.png)

| 状态 | 实例选择                                                 | 内容区域                                     |
| ---- | -------------------------------------------------------- | -------------------------------------------- |
| 展开 | 左侧约 240px 导航，按个人、公共 / 系统、公共 / 共享分组  | 显示当前实例名称、归属、已编辑状态及视图内容 |
| 收起 | 侧栏完全移除；顶部改为同样分组的实例下拉，并保留展开按钮 | 表格、图表和仪表盘使用释放出的宽度           |

展开时当前实例名称作为内容标题；收起时定义名称作为页面标题，当前实例名称显示在下拉中。归属与 [已编辑] 始终紧邻当前实例名称，不能让用户误以为修改的是整个页面定义。保存视图、另存为和还原更改与实例配置关联，刷新与当前查询关联；具体控件位置在组件设计中确定，并在三类视图中保持可识别的一致性。

宽容器初始展开。窄容器暂时使用收起布局，恢复足够宽度后沿用用户原来的展开偏好。收起后不保留图标窄栏。导航展开状态仅保存在当前页面，切换实例时保留；本期不增加跨页面的偏好持久化接口。

导航只控制实例列表的显示位置。一次收起或展开须满足：

- 当前实例 ID、视图形态与实例列表一致；选中项和个人 / 公共分组一致。
- 筛选表达式、简单 / 高级模式、排序、列配置、页码、游标、行选择和草稿保持不变。
- 核心运行对象与面板运行状态继续使用，不重复加载定义或实例，不重新查询。
- [已编辑] 和正在进行的保存状态保持不变。
- 可通过键盘操作收起 / 展开按钮；按钮具备明确名称和 `aria-expanded`。收起时焦点移到对应的展开入口。

效果图两侧采用同一筛选模式以强调导航变化。高级筛选展开时也能收起侧栏，不会自动降为简单模式。

## 2. 记录视图

记录视图服务“找到记录 → 执行业务操作 → 确认处理结果”。它包含实例导航与配置管理、全局业务操作区、筛选、记录内容、行操作和分页。业务主操作优先于保存视图、列设置等辅助操作，不能把整个页面组织成视图配置编辑器。

全局业务操作由宿主提供，例如新建、导入或按条件导出；不依赖某一行的动作在结果为空时仍可使用。主操作、次操作及更多菜单按业务频率组织，具体组合由操作组件打磨。保存视图要明确其对象是查看配置，不表示业务记录已经提交。

行操作针对稳定记录标识执行，例如审核、发货或停用。宿主结合权限与当前业务状态提供可见性、禁用原因、业务表单及执行中 / 成功 / 失败反馈。一个动作的等待或失败不应遮住整个记录列表。业务成功后刷新列表，记录因不再满足筛选而消失时仍保留可理解的处理反馈；刷新失败不能误报业务失败或自动重发业务动作。

全局操作的目标必须明确区分业务资源、当前查询范围与显式选择。宿主启用批量操作时，首期仅使用当前页明确勾选的记录并展示已选数量；筛选、排序、分页改变或结果刷新后清空选择，不把当前页当作全部筛选结果。导航收起不改变选择。

简单筛选横向紧凑排列，空间不足时整组换行，条件之间固定 AND，不额外显示 AND 文字。单个字段过滤器在添加时绑定一个字段，字段名固定显示，操作、值和删除入口具有共同视觉边界。高级筛选区分容器（AND、OR、NOR、ELEMENT_MATCH）与非容器：容器表达层级和作用域，普通条件仍按内容宽度排列，不强制占整行。筛选区域的展开状态与实例导航独立。界面使用业务字段名和操作文案，不要求用户编写 JSON。

过滤器采用手动查询：先编辑条件，点击“查询”统一生效。输入中的修改显示“待查询”，列表及业务操作仍使用已应用条件；条件提交进入实例草稿后，才按保存基线判断 [已编辑]。清空条件仍需查询，撤销筛选修改恢复已应用条件。存在待查询修改时，保存视图和另存为提示先查询或撤销。组件的输入输出、值控件与状态规则见 [过滤器组件设计](2026-09-05-wow-view-engine-filter-design.md)。

表格使用清晰的表头与轻量行分隔，金额右对齐、数值等宽，状态通过有文字的色彩标签表示。单元格和操作单元格沿用统一行高及焦点规则，实际内容由扩展组件提供。操作单元格呈现 `RecordView` 的行操作，业务行为不依赖表格行索引或列对象，后续卡片可以复用。

列设置通过表格右上方浮层提供，包含列名称、顺序调整、显隐和宽度；顺序调整同时提供键盘入口。表头可拖动列边缘设置宽度。显示顺序与数据排序分开表达：表头排序箭头表示 Wow 查询排序。

收起导航不会增删列或改写已保存宽度。容器不足以容纳列时，表格内容区横向滚动，实例选择与保存操作仍可访问。首期不展示尚未交付的卡片切换入口。

## 3. 分析视图

![分析视图](assets/wow-view-engine/analysis.png)

分析视图以统计口径和结果解读为中心，保留统一实例管理能力，围绕筛选、维度、指标与聚合方式组织主要操作。配置使用业务名称；分组结果显示服务端返回的别名对应名称。图表和分组表的组合由分析任务决定。

表格、指标卡、柱状图和折线图属于分析实例的展示配置。指标卡需要无分组查询；界面在切换时明确说明这一要求，不静默清空用户的分组。图表与结果表使用同一批聚合结果，不对截取的分组结果另算全局总额。

分组结果行不是业务记录，不能自动套用记录视图的审核、发货等操作。宿主提供进一步查询入口时，以当前筛选与分组值明确明细范围，并决定目标页面；缺少接入时不放置无效入口。

示例图展示 9 月 1 日至 5 日的分组结果，日期与数值均为视觉演示数据。展示上限保留在结果区，不占据页面标题或主操作位置。

## 4. 仪表盘

![仪表盘视图](assets/wow-view-engine/dashboard.png)

仪表盘默认服务观察与定位问题，保留统一实例管理能力，将筛选区标明为全局筛选。内容按网格排列独立面板：指标卡、分析图表、记录列表。布局编辑按需进入，不能让配置操作占据持续查看的主要空间。

全局条件仅叠加到已绑定面板的查询，不改变子实例保存基线。指标由各自查询产生。图中指标卡与图表可以展示相关数值，但不能据此把分组结果求和当作指标查询的实现。

布局设置提供面板引用、位置和跨度调整。默认 UI 的“编辑原视图”入口由宿主导航到独立子实例，编辑与保存作用于该子实例，并说明其已保存修改会被其他引用方在下次加载时采用。仪表盘的保存只处理本身的布局、引用和全局筛选。记录面板可以保留自己的分页和宿主行操作；不显示尚未承诺的拖放手柄。收起页面导航时只重新分配可用宽度，不写回布局、不重建面板、不触发查询。

面板加载、空结果、查询失败和无权访问分别在对应面板内显示。其他面板继续显示；局部重试只重试该面板。

## 5. 保存与另存为

![另存为视图](assets/wow-view-engine/save-as.png)

| 状态或操作     | 默认 UI                                                              |
| -------------- | -------------------------------------------------------------------- |
| 已保存         | 实例名旁无 [已编辑]；有保存权限时，保存按钮禁用，另存为仍可用        |
| 配置改变       | 实例名旁以默认 Badge 显示 [已编辑]；保存使用当前草稿                 |
| 还原更改       | 存在配置修改时提供入口，明确恢复当前实例的已保存配置；不撤销业务操作 |
| 正在保存       | 按钮显示保存中并阻止重复写入；配置仍可继续编辑                       |
| 保存成功       | 依照实际草稿与保存基线决定是否去掉标记；保存期间的后续修改继续保留   |
| 保存失败或冲突 | 在保存操作附近显示可读错误，保留草稿与 [已编辑]                      |
| 无保存权限     | 不提供覆盖保存操作；有另存权限时仍提供对应另存入口                   |

另存对话框包含视图名称和可见范围，默认个人；有权限时提供公共 / 共享，不提供系统分类。名称必填，校验信息位于对应字段下方。取消或关闭只关闭对话框。提交期间不允许重复创建。

保存反馈明确针对视图配置；业务操作及业务表单分别反馈，不共用 [已编辑]。正式保存、另存期间继续编辑、切换视图以及失败后的草稿处理，以核心设计的保存契约为准。效果图不代表已连接远程保存接口。

## 6. 单个组件的打磨与验收

- shadcn/ui + Base UI；尽可能复用预制组件、默认主题与内置 variant / size，包括输入组合、按钮、模式切换、标记和焦点样式。定制限于布局与组合，不另设组件配色、圆角或字体规范。通过 `--fve-*` 映射默认语义变量，支持宿主主题；效果图中的颜色和尺寸不覆盖此规则。
- 状态必须有文字，不能只靠颜色；弹层具有标题，键盘焦点可见且关闭后返回触发入口。
- 三类视图保持一致的实例管理含义，各自确定业务工具栏与主操作。图中业务中心等面包屑属于宿主示例，不新增 lib 管理的业务导航。
- 先打磨 RecordView 的全局操作区、行操作及执行反馈，再验证筛选、表格和其他视图专属交互。每个组件明确任务、输入输出、权限、加载与失败状态、键盘操作及响应式行为。
- 逐项验证侧栏与下拉等价、宽窄容器切换、简单 / 高级筛选、列宽 / 顺序 / 显隐、保存、另存与还原。收起操作前后检查请求次数和草稿一致；业务处理不能改变视图配置基线。
- 图表、表格和面板可适配容器；不能用截断内容隐藏实例选择、保存按钮或关键错误。
- 高级筛选以完整 Wow 表达能力、参数保留与输入反馈为验收依据。代表性组件状态用于验证交互，不要求先为每个操作生成效果图。示例数据应自洽，分页数字和标记位置等细节在对应组件中校正。
- 后续实现须在浏览器中按用户任务验证。效果图用于检查整体方向，不要求逐像素一致；当前交付为设计，不能把图片检查或仓库单元测试视为 UI 交互已经通过验证。
