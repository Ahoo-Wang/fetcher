# 视图管理：设置个人默认视图

日期：2026-09-10。状态：已实现并通过本地单元测试、类型检查、构建、浏览器与文档验证；整体审查通过，未发布。

## 目标与已确认行为

用户在“管理视图”中指定下次进入当前页面时自动打开的视图。偏好按当前宿主用户作用域和 `definitionId` 隔离，每个作用域最多一个默认实例。

- 当前可见的个人、共享、系统视图均可设为默认；不要求实例编辑权限。
- 设置成功后更新默认标记，不切换当前视图，不提交或丢弃任何未保存修改，不触发记录查询。
- 默认项支持取消。取消保存为 `null`，下次进入不自动选择实例，沿用现有加载语义。
- 默认实例被删除或不可见时，沿用现有本地宿主规则，按用户排序回退到第一个可见实例；无可见实例时为 `null`。
- 取消默认与默认失效不同：显式 `null` 不自动回退到第一项。
- 更改排序不隐式设置默认；普通视图切换也不改变默认偏好。删除导致默认失效时，删除事务同时保存受影响用户的回退结果，避免后续排序再次改变默认。

## 方案选择

采用扩展现有 `ViewPreferenceService` 的方案。`ViewInstanceList.defaultInstanceId` 和本地 `ServiceState.users` 已有默认值字段，加载器已使用列表返回值选择初始实例，因此无需新增偏好存储或修改实例内容结构。

不采用“记住最后一次打开的视图”：它会让临时切换覆盖用户明确指定的默认值。不增加管理员全局默认、跨设备同步框架、额外依赖或构建配置。

## 当前代码依据

- `ViewManager` / `ViewManagerRow` 已提供改名、删除、排序及统一忙碌和错误反馈。
- `ViewPreferenceService` 目前仅声明可选 `saveOrder`。
- `StatefulViewHost` 按用户保存 `order` 和 `defaultInstanceId`；列表读取已处理不可见默认项的回退。
- `ViewLoader` 用 `defaultInstanceId` 初始化 `selectedInstanceId`，但引擎快照尚未单独保留默认实例。
- `ViewManagement` 承担管理操作；`ViewEngine` 提供公开委托和能力快照。
- Memory 和 IndexedDB 宿主共用 `StatefulViewHost`；开发 HTTP 宿主已有偏好适配及服务示例。

## 代码质量约束

用户明确要求不考虑兼容性，保持架构和代码清洁。统一当前契约，不为旧手工快照增加可选字段、默认值兜底或适配分支；复用现有职责和真实能力模型。

## 契约与职责

以下是待实现的接口设计，并非对当前已导出 API 的描述。

偏好服务增加可选方法：

```ts
saveDefault?(definitionId: string, instanceId: string | null): Promise<void>;
```

成功返回表示偏好已保存。`null` 表示取消。宿主校验定义、当前用户及实例可见性；拒绝未知、不可见或属于其他定义的 ID。默认偏好不更新实例 revision、内容或用户排序。

引擎增加 `setDefaultInstance(instanceId: string | null)` 和对应能力查询，在快照中独立保存 `defaultInstanceId`。默认实例与当前选中实例不得混用；切换选中项不能影响默认标记。能力由宿主是否提供保存方法决定，不复用改名、删除或排序权限。

复用 `ViewManagement` 和现有管理动作反馈，不新增独立服务层。加载时记录宿主返回的默认值；显式设置只在保存成功后发布默认值。默认项被当前引擎删除时，同步按剩余顺序更新默认标记；当前选中项的删除切换保持原有规则。再次完整加载时以宿主列表结果为准。

Memory 和 IndexedDB 在共用宿主事务中仅更新当前用户的 `defaultInstanceId`，无需存储迁移。失效 ID 的读取回退保持既有规则，不把显式取消改写成回退。

开发 HTTP 示例增加与现有 `/order` 同级的 `PUT /default`，请求体为 `{ instanceId: string | null }`，成功响应沿用现有无返回内容约定。客户端适配、示例服务及双语接口说明同步更新；这是示例契约的新增路由，不假设外部服务已支持。

宿主未提供 `saveDefault` 时，引擎调用明确报不支持，界面隐藏修改默认的操作；列表默认值仍可加载和展示。这是宿主能力边界，不保留兼容层或旧状态格式。引擎的 `defaultInstanceId` 和 `setDefault` 能力字段均为必填，状态由引擎完整初始化。

## 管理界面

在现有每行操作区提供带可访问名称的“设为默认”按钮；默认项显示“默认”标记，并提供“取消默认”。沿用现有按钮样式、键盘交互和忙碌反馈。

对话框说明补充“默认视图仅对你生效，下次进入时自动打开”。保存期间禁止重复提交及关闭对话框；成功后保留当前焦点和打开状态。失败保留先前标记并在现有错误区域反馈，允许重试。

## 异常与并发

- 设置前校验当前加载状态、目标实例及宿主能力；保存端再次校验可见性。
- 同一引擎的默认保存禁止重入；与目标删除协调，不能在删除完成后由迟到响应重新标记已删除实例。
- 沿用引擎生命周期检查；完整重载或销毁后，旧响应不得发布状态。
- 传输失败不宣告成功。结果未知时提示用户重试或重新加载核对；同一值重复保存是幂等操作，不新增请求回执存储。
- 不引入乐观更新回滚、全局队列或后台自动重试。多个独立客户端的成功写入沿用现有存储事务语义，最后一次提交生效。

## 验收与验证

使用现有 Vitest、宿主契约测试和 Storybook 交互测试，不增加测试框架。

1. 将非当前实例设为默认：标记更新，当前选择、草稿、查询次数不变；重新进入自动选择新默认。
2. 替换默认只保留一个标记；取消后重新加载保持 `null`。
3. 可见的系统和共享实例即使不可编辑也可设为个人默认；其他用户及其他定义偏好不受影响。
4. 保存失败、重复提交、目标删除及重载/销毁后的迟到响应不会产生错误标记。
5. 删除或失去默认实例可见性时回退第一项，空列表回退 `null`；显式取消不触发回退。
6. Memory、IndexedDB 和 HTTP 示例均覆盖设置、取消和读取；IndexedDB 重新创建宿主后能读取已保存偏好。
7. 无保存能力的宿主仍可加载，隐藏修改操作；管理按钮可通过键盘使用，错误有可访问反馈。
