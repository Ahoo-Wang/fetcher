# 分析视图适配 Wow 扩展聚合 API

## 状态与依据

用户已确认完整适配范围、纳入对抗性审查的五项修正，并通过本文审阅。设计已批准并实施；验证记录见相邻 plans/2026-09-13-wow-analysis-aggregation.md。

- Fetcher 基线：`0e2ac48a`，包含聚合协议更新 `0510d151`（#1459）。
- 后端协议依据：本地 Wow `fd1b3cd46`；这不是对部署中服务版本的确认。
- 核对源码：Fetcher `packages/wow/src/query/aggregation.ts`、view-engine 的分析模型、编译器、编辑器、结果准入、图表投影和查询生命周期；Wow 的 `AggregationQuery.kt`、`QuerySchemaValidation.kt`、`MetricFilterValidation.kt`、`EmptyAggregationValues.kt`。

## 目标与边界

在现有配置 → 编译校验 → aggregate 查询 → 表格/图表链路中，完整接入去重计数、百分位、指标独立过滤、派生指标、聚合后过滤、缺失值归组和日期补桶。复核已有总体标准差与总体方差的结果语义。

复用现有数据源、请求调度、保存/恢复、过滤控件和图表，不增加依赖、不修改构建配置、不另建分析引擎。统计计算由 Wow 执行；前端不重算派生值、不自行补桶、不对分组结果做二次汇总。

示例：按渠道统计订单数、已支付订单数、去重客户数和支付金额 P95，计算支付率，再筛选订单数不少于 100 的渠道。明细作用域的计数表示明细数，界面必须显示当前统计范围，不能沿用订单数口径。

## 能力声明

扩展现有 AnalysisCapability，而不是建立另一套注册中心：

- 字段级声明去重计数与百分位能力，沿用已有分组、数值函数和表达式能力。
- 查询级声明指标过滤、派生指标、结果筛选、缺失值归组、日期补桶能力。
- 新增能力未声明时关闭。最终准入同时要求服务能力、字段能力、字段类型和当前作用域合法；任一条件不满足都拒绝编译。
- 数组明细作用域保留自身字段能力，宿主声明的服务能力在作用域切换后仍受约束，不能通过进入明细作用域放宽权限。
- Wow Schema 适配器扩展选项以接受宿主的服务能力声明。字段 Schema 可以限制字段适用性，但不能据此推断数据库版本、部署支持或查询精确性。

现有功能的授权方式保持原语义；不额外依赖运行时能力探测接口。服务端始终是实际授权与执行边界。

## 配置与引用

沿用 AnalysisComponentConfig 的组件 ID、名称、属性与字段绑定结构。新增独立指标筛选配置、派生表达式草稿和结果筛选草稿；具体 TS 声明沿用现有命名风格。

- 普通表达式仍引用字段，支持字段、有限数值常量和四则运算。
- 派生表达式引用稳定的指标组件 ID，支持常量和四则运算。编译时根据当前配置将 ID 转为 Wow alias。
- 派生指标只能引用其前面声明的非 ANY 指标，包括前面的派生指标。禁止自引用、前向引用、失效引用和维度显示字段引用；不引入自动拓扑排序。
- HAVING 同样持久化指标 ID，编译为 alias；可以引用已声明的非 ANY 指标，不受派生指标的前向引用限制。
- 改标题或 alias 不改变引用目标。删除后保留失效引用并阻止查询，不能按同名 alias 自动重新绑定。重新排序导致前向引用时保留草稿并明确报错。
- 现有按 alias 存储的排序和展示配置纳入改名、删除回归；不扩大为无关的全仓引用模型迁移。编辑器提供 alias 改名操作时，必须原子更新受影响的排序和展示绑定；底层直接传入的失效配置仍由准入拒绝。

输入允许保留尚未完成的数字文本，保存/恢复遵循现有结构校验与语义编译分工。空白、NaN、Infinity 或未完成公式不可发起查询；错误指出具体指标或筛选节点。

已有分析配置省略新增选项时保持既有请求语义。view-engine API 尚不稳定，允许清理过时内部结构，更新所有调用者、测试和文档；不新增历史版本兼容层。

## 编译与协议约束

集中复用表达式遍历和过滤编译机制，但不把不同位置的准入规则混为一谈。内置组件和自定义编译器输出都经过重建与复验。

### 指标与过滤

- 去重计数的直接字段引用按 TERMS 或 NUMERIC 能力验证，支持字符串客户 ID 等合法字段；常量合法，二元表达式中的字段按数值表达式规则验证。不能借用 SUM 等函数授权来验证去重。
- 百分位及普通数值表达式要求对应数值能力；百分位参数必须是严格介于 0 和 100 的有限数值，中位数为 50。
- 非派生指标过滤只影响当前指标。派生指标不允许独立记录过滤，应过滤其引用的基础指标。
- 指标筛选使用当前聚合作用域的标量字段和专用操作符集合。拒绝 SEARCH、ELEMENT_MATCH、数组及含数组备选的字段；复验自定义过滤编译器的输出，不能只限制 UI 选项。
- 根过滤与宿主 scopeFilter 保持现有合并路径；元素过滤和指标过滤不能替代根数据范围。当前作用域内同名字段不得回退匹配根字段。

### 结果筛选与分桶

- HAVING 支持比较、BETWEEN、非空 IN、IS_NULL、非空 AND/OR；只引用非 ANY 指标，必须至少有一个分组。
- 递归校验操作符、布尔参数、有限数值、区间上下界和引用；省略结果筛选时不生成 having。
- missingKey 仅适用于支持 TERMS 的单值字符串字段，值为非空白字符串。它是实际桶键，不只是显示标签；与真实同值合并属于统计语义，UI 应说明这一点。
- dense 必须是布尔值，仅允许唯一分组维度为日期分桶时开启。缺失日期范围取决于服务端真实结果范围，不承诺填满用户筛选区间；无数据时不生成日期范围。
- 服务端先产生聚合和派生结果，再执行 HAVING、排序及 limit。HAVING 可以再次移除补出的空桶，因此“补齐日期”不保证最终图表没有缺口。

### 请求预算

- 普通指标表达式（NUMERIC、DISTINCT_COUNT、PERCENTILE）整请求累计最多 256 个节点，每棵树深度最多 8。
- 派生表达式整请求单独累计最多 256 个节点，深度最多 8。
- Wow 当前 HAVING 校验深度最多 8，没有单独的 256 节点协议限制；不得把它描述为后端限制。前端额外限制 HAVING 为 256 节点，作为编辑和编译资源预算，错误提示明确其前端来源。
- 沿用配置大小和过滤树资源限制，保留分组 32、指标 64、有效排序 32、元素链 5、结果 10000 的协议上限；宿主可以收紧，不能放宽。
- 维度显示字段生成的 ANY 计入指标数量。自定义编译器生成的表达式计入相同请求预算。

## 编辑器职责与体验

将指标编辑职责从较大的 AnalysisEditor 中抽出，页面继续负责整体配置布局与变更提交，不建立通用表单框架。

- 基础指标卡片提供统计方式、字段/公式、统计条件；去重计数与百分位有独立统计方式，百分位支持 50/95/99 快捷选择和合法自定义值。
- 派生指标卡片提供指标公式，只列出可引用的前置指标，显示业务标题。复用公式的常量、运算符等交互，但字段表达式与指标表达式保持明确类型边界。
- 结果筛选独立展示，使用指标、条件、值及全部/任一条件组，不让业务用户输入 HAVING JSON。
- 分组设置显示缺失值归组和日期补桶；不满足能力或组合约束时明确不可用，已保存但现已失效的配置保留可修复入口。
- 非法草稿给出行内错误并阻止查询。保持已有 disabled、键盘操作、标签关联和窄屏布局；控件卸载不能清除尚未修复的校验错误。

## 结果、单位与图表

统计语义与显示格式分离：可加性只按明确的聚合类型判断，不能由 format=count、整数外观或单位推断。

- 去重计数和 COUNT 都按非负安全整数准入，空桶为 0，但去重计数默认禁止饼图和堆叠。
- 百分位、派生指标、AVG、MIN、MAX、STDDEV、VARIANCE 默认禁止饼图和堆叠；不为特定派生公式引入可加性推理。
- 保留 SUM/COUNT 现有可加图表规则，普通表格、非堆叠趋势与比较展示接受合法新数值指标。
- 空桶的数值指标（包括 SUM）、ANY 和百分位为 null。派生指标可能为 null，也可能由常量得到数值；不能一律补零或强制为空。
- 除零、空操作数与非有限计算结果依照服务端响应处理；null 展示为无值，图表不能伪造零点。非法非有限响应仍拒绝发布。
- STDDEV 与输入同单位，VARIANCE 为平方单位；去重计数不继承客户 ID 等源字段单位。数值表达式沿用已有单位推导，无法确定的单位不猜测。
- 比例不得自动继承基础金额字段的货币格式；方差也不能沿用表示原单位的货币格式。派生指标提供明确的数字/百分比展示设置，复用现有 Intl.NumberFormat 格式化链路，原始数值不乘 100。现有 AnalysisPresentation 没有百分比设置，本次在指标配置中补充该入口。
- 百分位标明近似统计。去重计数说明精确性取决于后端（当前 Wow 的 ES 可能近似、Mongo 为精确）；不宣称从结果整数外观能够判断精确性。

请求调度、取消、过期结果隔离、保存与已执行结果分离仍复用现有生命周期。失败保留的旧结果继续关联旧 plan/config，不用新配置的单位、标题或筛选说明重新解释。

## 验收场景

每项均验证对用户可观察的行为或请求/结果契约，不以组件拆分或测试数量作为通过依据。

1. 字符串客户 ID 去重成功；同字段用于百分位或算术表达式被拒绝。数值去重与百分位请求匹配 Wow JSON。
2. 同一客户跨渠道重复出现时，去重计数即使使用 count 格式也不能进入饼图或堆叠；SUM/COUNT 的既有有效场景不退化。
3. 订单根状态和明细状态同名，验证根、元素、指标过滤各自正确绑定；篡改配置及自定义输出不能注入禁止字段或操作符。
4. 支付率引用稳定 ID；改名仍指向原指标，删除并创建同 alias 指标不得重新绑定。验证前向、自引用、ANY 引用及派生链。
5. HAVING 引用改名安全；拒绝维度、失效 ID、ANY、无分组、空集合/条件组、反向区间、非有限输入及非法布尔值。
6. 两棵各 255 节点、深度合法的普通表达式组合被拒绝；派生预算独立累计，验证精确边界、自定义输出和深度限制。HAVING 前端预算另测。
7. 非字符串 missingKey、空白桶键、非布尔 dense、多维 dense 被拒绝；字符串真实桶键与缺失值合并的语义有明确说明。
8. 空桶中 COUNT/去重为 0，SUM/P95 为 null，常量派生和除零派生分别正确准入。HAVING 可移除空桶，无数据不伪造日期范围。
9. 缺失、关闭或作用域不匹配的能力均拒绝；旧配置未启用扩展时保持原请求语义。
10. 保存重开、恢复、改名、排序、图表切换及 dashboard/embedded 查询沿用完整配置；取消、过期响应和失败保留旧结果不改变已执行语义。
11. 方差单位、货币格式与比例显示正确；结果校验拒绝负计数、小数计数、非安全整数和非有限数值。
