# Storybook 全量重构设计

## 目标与状态

将整个 Storybook 组织为可运行的接入文档，同时保留浏览器交互回归验证能力。优先帮助使用者找到最小示例、理解 API 和独立操作场景；以清晰职责、可重复测试作为维护约束。

用户已确认重构方向、目录范围、代码边界与验收方式。文档已获用户确认，实现与验证记录见对应实施计划和迁移清单。

本设计取代 2026-08-28 Storybook 设计中限制重构范围、保持旧导航、按标题集中配置场景说明的约束。旧文档保留为历史记录。

## 范围

- 覆盖现有 Overview、HTTP、事件、存储、React Hooks、View Engine、Viewer 的全部故事，以及 `.storybook` 共享配置。
- 同步调整受影响的 Storybook 测试配置、lint 文件匹配、首页链接和开发验证脚本地址。
- 保留现有包内公共接入示例并复用；如需调整故事专属测试接入，限定在示例和开发验证层。
- 不修改包的运行时 API，不升级或新增依赖，不为目前没有故事的包补建示例。
- 不拆成多个 Storybook，不建立通用故事生成框架，不机械拆分小文件。
- 不增加旧故事地址兼容层；仓库内消费者必须同步迁移。

源文件按模块归属组织，不要求文件夹逐层镜像展示标题。模块内就近维护故事、演示组件、夹具和交互测试。仅实际被多个模块使用的辅助设施放入共享目录。

首页覆盖上述全部能力入口，提供最小接入路径，并明确开发实验的外部条件。名称以中文行为说明配合公开 API 英文符号；不把已有英文内容的逐句翻译作为独立任务。

Record View 原有 18 个故事逐一映射到主题页。Library Delivery 中的公共包接入内容归入快速开始和扩展接入，LocalStorage 与 HTTP 场景移入开发验证。原有断言必须在迁移清单中有明确去向。

## 职责和依赖

| 层次               | 职责                                   | 边界                                     |
| ------------------ | -------------------------------------- | ---------------------------------------- |
| 全局配置           | 通用参数、导航顺序、基础样式、测试入口 | 不根据故事标题选择 Provider 或业务说明   |
| 模块元数据与装饰器 | 模块所需 Provider、场景说明、布局      | 在对应模块显式引用；通用展示外壳可以共享 |
| 故事               | 名称、初始参数、场景组合、文档说明     | 不承载复杂服务实现                       |
| 演示组件           | 可手动操作的公开 API 接入              | 展示与测试复用同一实现                   |
| 夹具               | 确定性数据、服务替身及生命周期         | 状态属于独立场景；清理责任明确           |
| 交互测试           | 用户操作和可观察结果断言               | 不复制业务实现或改写运行时契约           |

Ant Design Provider 仅由使用它的模块显式安装；View Engine 保持自身样式与主题边界。共享场景外壳保留必要的目的、操作和预期结果说明，避免在全局配置中维护标题到说明的映射。

继续保持现有导入验证边界：公共包交付示例解析到构建产物，不为方便开发将 View Engine 改为源码别名。其他包当前的源码别名策略不在本次调整。

## 展示与回归执行

- 普通展示故事独立打开后停留在可理解的初始状态；允许必要的初始化读取，不自动创建、删除或更改用户选择。
- 无副作用的渲染断言可以留在展示故事。执行复杂交互的回归故事复用展示组件和参数，通过 Storybook 原生标签保留测试执行，并从默认导航和自动文档中排除。
- 不通过判断测试环境，在同一演示实现中改变业务行为。
- 错误、空态、加载等演示需要可重复的初始条件；不能依赖先访问另一故事或等待上一段自动操作完成。
- 文档按主题控制篇幅，保留最小示例、用途和接入说明；完整业务演示提供独立 Canvas 入口。代码展示必须对应真实接入，避免只露出不具参考价值的内部包装器。
- HTTP 实验保留单独的端到端验证入口，不混入无需外部服务的默认测试集合。服务未启动时不得让普通文档页面发起该实验请求。

采用 Storybook 原生 `dev`、`autodocs`、`test` 标签，不引入另一套故事注册机制。具体标签组合在实施时通过已安装版本验证。

## 状态、错误与清理

每个场景独立创建可变状态；切换、重新运行或卸载时清理请求、定时器和监听器。共享数据可以不可变复用，共享可变服务状态不能跨故事泄漏。

检查现有 fetch 替身的安装与恢复方式，覆盖 Docs 同页多示例及测试重复运行；不能用未经验证的全局替换造成相互覆盖。沿用现有工具修复故事层问题，不新增模拟服务依赖。

只有明确标记的持久化验证保留跨刷新状态，使用隔离的存储范围，并提供重置入口；重置不清除其他示例或用户存储。失败、重试、过期响应和权限等已有覆盖继续保留。

## 迁移与验收

实施前记录当前故事索引及交互断言，维护旧故事到新展示故事、回归故事的映射。测试数量可因职责分离变化，验收依据是行为覆盖而非总数相等。

已知地址消费者包含 Overview、manager 首页，以及 `verify-view-host.mjs`、`verify-http-view-host.mjs`。实施时继续检索仓库内旧故事 ID，逐项迁移；生成索引中的新地址应真实存在。

验收要求：

1. 全部现有故事有去向；首页包含所有能力入口；普通文档不嵌入依赖独立服务的实验。
2. 展示故事可独立手动操作；复杂测试故事不污染默认文档；重复运行和切换不会泄漏状态。
3. Storybook 静态构建和完整浏览器交互测试通过，保留既有可访问性检查强度。
4. 修改文件的 ESLint 与格式检查通过，View Engine 的 React/Compiler 严格规则保持生效。
5. 在正常、窄容器、深色以及文档和独立 Canvas 场景进行浏览器检查，确认导航、弹层、滚动和布局正常。
6. 验证迁移后的 LocalStorage 刷新恢复与 HTTP 端到端脚本入口；涉及公共包接入的调整继续通过打包验证。
7. 对受影响的包运行测试和构建；提交实现前按仓库要求运行 `pnpm test:unit`。

## 实施顺序

先建立覆盖与路由清单，再整理全局配置和模块边界；逐模块迁移故事、文档及测试，最后更新首页和开发验证入口并执行完整验收。后续实施计划将给出具体文件和检查命令。

## 设计自检

- 范围覆盖全部现有 Storybook 内容，不扩展运行时能力。
- 目录按使用路径组织，代码按职责组织，两者不强制逐层一致。
- 展示和回归共享实现，隔离执行入口；不删除现有断言来获得测试通过。
- 实验入口隔离、公共产物验证、存储边界和路由迁移均有验收要求。
- 不需要新增依赖、生成框架或独立 Storybook 实例。
