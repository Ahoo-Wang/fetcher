# AnalysisView 首版设计

日期：2026-09-10。状态：历史设计及审查记录，尚未实现。当前统一评审稿为 [View Engine 与 AnalysisView 重设计](2026-09-10-analysis-view-redesign.md)；本文中 applied 状态、保存前必须应用等旧规则不再作为后续实施依据。

用户补充要求：必要时重构架构分层，保证职责清晰、高内聚、低耦合、高可维护性。该授权适用于本功能需要调整的现有结构。

## 1. 目标与交付范围

完成“配置筛选、维度和指标 → 应用聚合 → 查看结果表 → 保存并恢复实例”的闭环。记录和分析实例支持在同一 ViewPage 内导航，也可由宿主独立布局，使用同一套归属、权限和版本冲突语义。

首版支持 TERMS、HISTOGRAM、DATE_HISTOGRAM 分组，以及 COUNT、字段 SUM/AVG/MIN/MAX。允许无分组、多维度和多指标；字段能力由定义显式声明。继续复用现有简单/高级筛选器、主题和基础控件。

首版不包含指标卡、柱状图、折线图、仪表盘、表达式指标编辑器、ANY 编辑器、聚合数组展开编辑器、分组分页、全局合计、下钻或流式分析。已有筛选器的 elementMatch 能力保持可用；它筛选源记录，不等于聚合 elements 展开。

代表性场景：按订单状态分组，计算订单数与订单金额合计；进一步加入按月份的日期分桶。显示名称修改、保存、重新打开后，字段绑定、别名和统计口径保持一致。

## 2. 当前代码事实与方案选择

- `record/recordModel.ts` 的 ViewInstance 仅为 RecordViewInstance，ViewDefinition 必填 rowKey 与记录布局，RecordQuerySource 至少需要 paged 或 cursor。
- ViewEngine 已拆分加载、查询、编辑、持久化和管理服务，但 SessionStore、ViewPersistence、ViewReload 等仍引用 RecordSession、RecordQueries 或记录专属会话构造函数。
- ViewPageContent 固定渲染 RecordView，页面属性也来自 RecordViewProps。
- LocalStorageViewHost 已实现私有/公共可见范围、版本比较、写入锁和创建幂等回执，应该沿用这些行为。
- Fetcher Wow 已公开 AggregationQuery、aggregation 构造器和 QueryApi.aggregate；聚合返回行数组，取消参数为 AbortController。

选择“共享实例生命周期，独立记录/分析会话”。独立复制分析页面和引擎会重复保存与恢复逻辑；任意视图插件引擎会引入首版不需要的扩展协议。内部只处理本次需要支持的 record、analysis 两种视图。

本设计继承 `2026-09-09-analysis-view-handoff.md`。当 9 月 5 日总设计中的手写 query 配置与交接文档冲突时，以组件配置为保存事实、查询为编译产物的规则为准。

## 3. 分层与依赖方向

| 层/目录                    | 所有权                                                                             | 不承担的职责                         |
| -------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------ |
| `view/` 核心契约与生命周期 | 实例身份、定义公共元数据、宿主接口、选择、加载、保存、权限、冲突核对、只读状态发布 | 记录分页、选择、聚合公式、结果表渲染 |
| `record/`                  | 记录配置、校验、编辑、分页/游标、记录选择、汇总、表格/卡片                         | 分析维度、指标和聚合结果身份         |
| `analysis/`                | 分析配置、字段能力校验、查询/schema 编译、结果校验、分析会话和默认组件             | 重复实现宿主持久化或业务记录操作     |
| `filter/`、`lib/`          | 既有过滤编译与编辑、纯工具、格式能力                                               | 依赖记录或分析引擎                   |
| React 页面组合             | 导航、实例管理、按 kind 选择视图、错误区域                                         | 编译业务统计或管理持久化事务         |

无 React 的契约、编译和会话逻辑由包核心入口导出。React 入口导出页面与编辑器；核心不能导入 React、DOM、TSX 或 CSS。

把确实共享的现有代码移至 view，保留记录专属实现。共享持久化只读取公共写入状态，通过内部明确的 kind 分派执行会话构造、内容比较、恢复与查询后续动作，不直接调用 RecordQueries。分派集中于组合边界，不在每个共享服务里重复判断所有视图细节。允许为两种真实实现定义小型内部操作契约，不建立公开插件注册生命周期、服务容器或继承层级。

共享状态存储发布判别联合会话；记录和分析的 patch、编辑入口必须先收窄类型。记录分页和行选择字段继续在 RecordSession 必填，AnalysisSession 不具有这些字段。不能通过给全部属性加可选标记解决类型冲突。

ViewPage、实例导航和管理 UI 移除对 RecordViewProps/RecordSession 的直接绑定。记录区域扩展仍只收到记录上下文；分析使用自己的编辑与结果组件。视图切换不重建全局引擎。

## 4. 公开契约与兼容策略

实例共享 ViewInstanceMetadata，配置使用 `kind: 'record' | 'analysis'` 判别。分析配置包含 filters、dimensions、metrics、sort、limit 和 table presentation。创建输入也必须保留 kind 与 config 的对应关系，不能直接对联合使用会丢失关联的普通 Omit。

新定义采用公共元数据与视图能力块：公共部分保存 id、title、sourceId、fields、timeZone 和过滤策略；record 能力块保存 rowKey、布局、列默认值与记录操作；analysis 能力块保存允许的分组/指标与查询限制。定义至少包含一种能力，实例 kind 必须与定义能力一致。记录专属参数在 record 能力内保持完整必填约束，纯分析定义不需要 rowKey。

兼容入口继续接受当前扁平记录定义，在加载边界归一化一次；不要求旧宿主重写已保存实例。新定义与旧定义不允许混合两套记录配置，遇到冲突明确报错。

公共类型采用默认 record 的 kind 类型参数保持旧调用的静态类型：ViewInstance、ViewHost、ViewEngine 及状态/选项/页面关联类型默认仍表达记录模式；分析或混合页面显式选择 analysis 或 record | analysis。RecordView 入口只消费收窄后的记录能力。禁止用 any 或不受保护的类型断言伪装兼容。

兼容验证包含旧宿主实现、已保存 JSON、旧 getSnapshot 记录字段访问和原有页面调用。仅增加联合成员不等于兼容，尤其需要检查宿主回调参数、创建输入和状态读取。若实现无法满足上述兼容约束，必须报告具体破坏性签名并先确定版本升级，不能静默改变公共 API。当前版本为 5.0.0，版本改动必须遵循仓库统一升级规则。

数据源沿用 `resolveSource(sourceId)`，返回记录查询能力、聚合能力或两者。分析仅要求 aggregate；执行前根据实例类型检查真实方法。宿主仍负责服务器字段权限、租户隔离及实际执行，前端能力声明不构成授权。

## 5. 组件配置、字段能力与纯编译

每个维度/指标保存稳定 id、component.name、JSON options、字段绑定、原始 props、alias 和 title。COUNT 不需要字段。新条目创建时生成合法、唯一、单段 alias，之后改名、调整顺序和恢复配置均保持 alias；删除并新建产生新身份。

维度字段能力显式列出可用分组方式：TERMS 面向声明类型的标量字段；HISTOGRAM 仅数值字段并校验有限正 interval；DATE_HISTOGRAM 仅时间字段且粒度必须在定义允许集合中。数值指标仅使用声明允许的字段与函数；COUNT 由分析定义显式允许。数组字段不能因其存在于过滤字段列表而自动获得聚合能力。

分析定义提供 maxDimensions、maxMetrics、maxSortFields、defaultLimit、maxLimit。内置 Wow 默认限制为 32、64、32、100、10000，宿主可收紧。编译检查显式排序加未覆盖维度的稳定排序后不超限；这些默认值依据本地 Wow AggregationQuery 源码，不代表已验证任何部署版本。

分析启用日期分桶时要求定义提供有效 timeZone，并在界面显示统计时区；编译把同一时区传给过滤器和日期分桶。不让未配置时区的浏览器本地值决定已保存统计的口径。仅记录定义继续保留已有默认时区行为。

沿用过滤器模式，React 扩展将编辑组件与纯编译能力一起注册，核心可直接接收无 React 编译注册。注册在引擎生命周期开始前准备并固定。组件编译只能贡献受声明能力约束的一个维度或指标及匹配 schema；核心统一校验 alias、字段、函数、分组类型、返回类型与资源限制，组件不能绕过能力声明注入任意查询。

编译一次返回 AggregationQuery 与有序结果 schema。schema 包含 alias、title、role、值类型、可空性、格式及原始字段绑定；table presentation 只引用 alias，不能改变统计语义。不另外保存第二份查询或从已编译查询反向构建编辑器。

未知组件、无效属性、重复 alias、无指标或非法排序阻断应用与保存，原始配置保留供修复。结构损坏的宿主数据作为加载错误；结构有效但组件缺失或定义能力已变更的实例可打开编辑，并显示定位到条目的校验错误。

## 6. 查询、结果与排序

使用既有 aggregation 构造器和 `aggregate(query, undefined, abortController)`。前端不从记录页数据计算统计，不重新实现传输 DSL。

结果必须是行对象数组，每行必须具有 schema 中全部 alias 的自有属性。按字面 alias 取值，不进行源字段点路径导航；额外返回字段不展示。校验失败使整次结果失败，不能展示部分通过校验的行。

- COUNT 必须为非负安全整数，不能为 null。
- 数值指标为有限 number 或 null；超出宿主精度约定的数据应由宿主处理，首版不提供精确十进制计算或把字符串偷偷转成数值。
- TERMS 值使用声明的标量类型或 null；数值桶为有限数值或 null。
- DATE_HISTOGRAM 结果按 Wow 分桶输出的 epoch milliseconds 校验，并按定义时区格式化；不根据字符串外观猜测单位。
- 分组键为维度声明顺序下的完整原始值元组，编码必须区分字符串、数字、布尔值和 null。重复元组是契约错误。无分组结果使用固定的单行身份。
- 有分组可返回零行；无分组允许零行或一行，多行是契约错误。零行显示“无聚合结果”，不能补造 COUNT=0；服务明确返回的一行 COUNT=0、SUM=null 则原样显示。

默认列为全部维度后接全部指标。首版支持列宽、列顺序和显示名称；所有查询输出保持可见。复用基础表格原语、格式化与适用的纯列交互逻辑，不给 RecordTable 填造 rowKey、选择或分页参数。单元格扩展若需要复用，必须剥离 RecordSession 依赖并提供分析结果上下文。

有分组时允许按结果 alias 设置服务端排序；点击表头仅对已应用口径排序并执行请求，保留未应用编辑。删除仍被排序或展示引用的指标/维度时提示修复引用，不能发送悬空 alias。无分组禁止排序；移除最后一个分组后若排序仍存在，显示校验问题并提供显式清除操作。

limit 始终发送有效正整数，界面显示“最多返回 N 行”，包括无分组至多一行的特殊展示说明。行数组没有 total/truncated 元数据，不能根据行数宣称完整结果。排序必须在服务端 limit 前生效，不在客户端对截取数据假装执行全量排名。

## 7. 草稿、应用结果与恢复

AnalysisSession 区分三份事实：最后保存的 baseline、当前实例配置与编辑草稿、最后成功结果对应的 query/schema/config 快照。请求中的目标另存于请求状态。查询内容比较排除标题、列宽等纯展示属性，保存 dirty 比较则包括用户保存的展示配置。

编辑筛选、维度、指标和上限不自动请求。点击“应用”后先完整编译；成功提交即更新当前可保存配置，再执行请求。请求失败不回滚有效配置，保留草稿和旧成功结果，并明确标注旧结果来自上次成功口径。结果的 schema 必须随成功结果一起保存，不能用新 schema 错配旧 rows。

保存要求当前编辑已应用且编译有效，与既有“先应用再保存”交互一致；不要求查询执行成功。有效统计定义可在服务暂时失败时保存，但保存按钮与结果状态不能暗示查询成功。恢复至已保存配置会撤销当前修改并重新执行；未知注册配置保持可见且执行受阻。

修改标题/列宽/显示顺序只改变展示和 dirty，不查询。已存在结果仅在 alias 和统计语义匹配时更新展示元数据。刷新和失败重试使用已应用查询，保留未应用草稿；初次加载有效实例自动查询。

每个请求绑定生命周期代次、实例 ID 和查询令牌。新查询、切换、重载或销毁时取消适用请求，返回时再次核对令牌，不能只依赖 abort。切回实例恢复其草稿；被取消且尚无有效结果的已应用查询按既有加载策略重新执行。

查询错误、配置错误和写入错误分别展示。实例操作在执行时复核权限，旧组件回调绑定原实例；写入结果不能覆盖请求发出后产生的新编辑。权限订阅是已有编辑/管理能力投影，不新增未经宿主定义的读取授权协议；用户/租户访问范围变化仍须销毁并重建引擎。

保存、另存、重命名、删除、刷新核对沿用现有 revision、requestId 和未知结果处理。响应校验必须包含 definitionId、kind 与配置关联，服务返回不同 kind 不能当成正常保存。重新加载发现 kind 不匹配时阻断自动合并并保留本地恢复信息，不跨类型套用草稿。

## 8. UI 与组件边界

ViewPage 保留实例导航、管理、保存/另存、主题和展开行为；按选中实例 kind 渲染 RecordView 或 AnalysisView。AnalysisView 组合已有过滤面板、维度/指标编辑区、已应用口径摘要、应用/撤销/刷新操作与结果表。

维度与指标提供添加、移除、上移/下移及配置控件，不引入拖拽依赖。COUNT 命名为“记录数”；数值指标同时显示字段与函数，日期分桶显示粒度与时区。输入验证定位到具体配置项，未知组件保留名称与移除入口。

窄容器允许配置区纵向排列、结果表局部横向滚动。所有按钮有可访问名称，错误/加载状态可被辅助技术感知，键盘可完成配置、应用、排序、保存与切换。局部组件失败由现有错误边界隔离；异步操作错误通过状态/Promise 通道处理。

首个可编辑实例仍由宿主初始配置提供，用户可另存为新实例；首版不额外建设跨种类空白实例向导。Storybook 必须提供开箱即用的记录/分析混合实例与纯聚合数据源示例。

针对性单元测试覆盖真实逻辑边界，类型检查覆盖联合收窄和旧调用兼容；Storybook 浏览器测试覆盖用户闭环和焦点/错误恢复。复用既有 Vitest、TypeScript、Storybook、Playwright，不增加测试框架。

协议样例首先对照 Fetcher Wow 类型和本地 Wow 源码；集成验证必须使用实际服务配置或明确启动的测试后端，不猜测接口、不修改生产服务。固定数据宿主仅证明前端行为，不能冒称后端聚合验证；外部服务不可用时单独记录阻塞。

交付源码、测试、混合/纯分析示例、README、中英文 wiki、`skills/fetcher-view-engine/references/api.md` 与必要的旧文档状态更新。运行受影响包及依赖构建、包测试/类型检查、Storybook 测试、文件级 lint/format 与 wiki build。提交前必须通过根目录 `pnpm test:unit`。

本次授权允许为上述边界重构既有代码；不包含引入新包、修改根 tsconfig 或构建配置。当前不需要新增外部依赖。

## 10. 规格自审与阶段边界

- 首版仅交付分析表闭环；图表/下钻不以占位按钮或通用框架形式提前实现。
- 配置是保存事实，query/schema 是编译产物；成功结果绑定自己的 schema，避免失败后统计口径错配。
- 明确 shared/record/analysis 的所有权与依赖方向，禁止共享持久化依赖记录查询实现。
- 明确旧记录默认类型、扁平定义归一化与实际兼容测试；不把联合扩展自动视为兼容。
- 区分纯分析定义、数据源能力和服务器权限；分析不伪造业务 rowKey。
- 明确无分组零行/一行、有分组空集、COUNT/null、上限、排序和日期单位的处理。
